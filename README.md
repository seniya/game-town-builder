# 작은 마을 복구 게임 (game-town-builder)

폐허가 된 섬에서 블록을 쌓아 공간을 만들면, 게임이 그 공간을 알아보고
주민들이 그곳에서 살아가기 시작하는 3D 복셀 게임이다.

> 죽어 있던 작은 마을을 내가 만든 것들로 살아 움직이게 만드는 게임

목표는 **드래곤 퀘스트 빌더즈 2 와 같은 구조의 게임** 이다.

## 세 개의 루프

```text
요청 루프   주민이 요구한다      →  만들어 준다        →  진행된다
인식 루프   자유롭게 짓는다      →  게임이 알아본다     →  주민이 쓴다     ★
성장 루프   감사 포인트가 쌓인다  →  마을의 종을 친다    →  마을 레벨이 오른다
```

셋 중 하나라도 빠지면 게임이 성립하지 않는다.

```text
요청만 있다   시키는 대로 짓는 심부름 게임
인식만 있다   무엇을 지어야 할지 모르는 막막한 샌드박스
성장만 있다   숫자를 올리는 클리커
```

가장 중요한 것은 **인식 루프** 다.
플레이어가 벽을 쌓고 문을 달고 침대를 놓으면, 게임이 "침실" 이라고 알아본다.
밤이 되면 주민이 그곳으로 걸어 들어가 눕는다.

## 현재 상태

```text
단계    문서 설계 완료. 구현 미착수 (TASK-001 부터 시작)
범위    수직 슬라이스 — 90~120 분
월드    128 × 64 × 128 복셀 섬 1 개
블록    22 종
방      5 종 (빈 방 / 창고 / 침실 / 주방 / 식당)
주민    3 명 시작 → 최대 5 명
레벨    마을 레벨 1 → 3
습격    2 회
```

## 기술 스택

```text
Node.js 24 LTS  /  pnpm
TypeScript 5.x (strict)
three 0.18x  —  WebGLRenderer (WebGL2)
Vite 8.x  —  SPA. React / Next.js 를 사용하지 않는다
Vitest 3.x
Web Worker (청크 그리디 메싱)
```

버전의 정본은 `package.json` 과 `pnpm-lock.yaml` 이다.
문서는 메이저 버전 제약만 규정한다.

### 게임 규칙은 렌더 엔진을 모른다

```text
src/game/**     three 를 import 하지 않는다. 순수 TypeScript
src/render/**   three 를 import 한다. 게임 상태를 읽어서 그리기만 한다
src/ui/**       DOM 만 쓴다
src/workers/**  순수 함수만 실행한다
```

ESLint 로 강제한다. 이 프로젝트는 엔진을 한 번 교체했고(Phaser 3 → three),
그 과정에서 이 경계의 가치가 증명되었다.

## 문서

읽는 순서가 정해져 있다.

```text
docs/project/GAME_DESIGN.md   왜 만드는가 / 무엇이 재미여야 하는가
docs/project/MVP_SPEC.md      무엇을 만드는가          수치와 조건식의 정본
docs/project/ARCHITECTURE.md  어떤 구조로 만드는가      인터페이스의 정본
docs/project/TASKS.md         어떤 순서로 만드는가      Acceptance Criteria 의 정본
docs/adr/                     구조적 결정 기록
docs/state/                   작업 완료 기록과 다음 할 일
```

에이전트 작업 규약은 `AGENTS.md` 에 있다.

### 주요 ADR

```text
011  2D Phaser 3 를 버리고 3D 복셀 Three.js 로 전환한다
012  Prefab 배치를 버리고 자유 건축 + 방 인식을 사용한다
013  감사 포인트와 마을 레벨을 도입하되 파생 지표와 축을 분리한다
014  복셀 월드를 청크 16³ 와 그리디 메싱으로 표현한다
015  3D 복셀 통행 그래프를 쓰고, 몬스터가 블록을 파괴할 수 있게 한다
```

폐기된 결정(001 / 002 / 005 / 009)도 삭제하지 않고 남겨 둔다.
그 결정이 왜 옳았고 언제부터 틀렸는지가 기록이다.

## 개발

```bash
pnpm install
pnpm dev      # 개발 서버
pnpm test     # Vitest
pnpm build    # 프로덕션 빌드
```

게임 로직은 three 와 분리하여 작성하므로, 테스트는 렌더러 없이 실행된다.

가장 많이 작성될 테스트는 **방 인식** 이다.
`tests/helpers/buildTestWorld.ts` 로 문자열 레이어에서 방을 그려 검증한다.

## 두 개의 검증 지점

```text
TASK-022   방을 만들고 인식시키는 과정이 즐거운가
TASK-033   밤에 주민이 내가 만든 방으로 걸어 들어가는 것이 만족스러운가
```

둘 중 하나라도 부정적이면 다음 Phase 로 넘어가지 않는다.
**콘텐츠를 추가해서 해결하려 하지 않는다.**

## 성공 기준

기능의 개수가 아니다.

플레이어가 직접 벤 나무로 쌓은 벽 안에서, 직접 놓은 침대에

밤이 되자 주민이 걸어 들어와 눕는 모습을 보면서

> 이 마을을 조금 더 키워보고 싶다.

라고 생각하게 만드는 것이다.
