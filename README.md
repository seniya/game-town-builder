# 작은 마을 복구 게임 (game-town-builder)

폐허가 된 섬에서 블록을 쌓아 공간을 가꾸고, 주민들의 일상을 지켜보는 3D 복셀 게임이다.

> **아름답게 만든 공간에서 정감 있는 주민이 실제로 살아가는 순간**

이 순간을 게임의 최우선 목표로 삼는다. 공간을 내 취향으로 꾸미는 즐거움과
그곳에 사는 주민에 대한 애착이 만나, 마을을 더 가꾸고 싶어지게 한다.
드래곤 퀘스트 빌더즈 2 의 자유 건축·방 인식·주민 생활 구조를 바탕으로 만든다.

동등하게 중요한 두 축을 함께 검증한다.

```text
시스템 축   플레이어의 건축 → 게임의 공간 인식 → 주민의 사용 → 플레이어의 관찰
감성 축     아름다운 공간 → 정감 있는 주민 → 생활하는 모습 → 내 마을이라는 애착
```

기능만 동작하는 시뮬레이션이나 아름답기만 한 디오라마에 머물지 않도록,
기본 팔레트·가구·밤의 조명·주민 실루엣과 생활 동작을 초기 검증부터 함께 다듬는다.

## 세 개의 루프

```text
요청 루프   주민이 요구한다      →  만들어 준다        →  진행된다
인식 루프   자유롭게 짓는다      →  게임이 알아본다     →  주민이 쓴다     ★
성장 루프   감사 포인트가 쌓인다  →  마을의 종을 친다    →  마을 레벨이 오른다
```

이 프로젝트에서는 세 루프가 함께 공간과 주민에 대한 애착을 만드는지 검증한다.

```text
요청만 있다   시키는 대로 짓는 심부름 게임
인식만 있다   무엇을 지어야 할지 모르는 막막한 샌드박스
성장만 있다   숫자를 올리는 클리커
```

시스템 축에서 가장 중요한 것은 **인식 루프** 다.
플레이어가 벽을 쌓고 문을 달고 침대를 놓으면, 게임이 "침실" 이라고 알아본다.
밤이 되면 익숙한 주민이 그곳으로 걸어 들어가 눕고, 아침에는 다시 일상을 시작한다.
방 인식에서 시작한 만족감은 아름답게 가꾼 공간에 주민의 생활이 더해질 때 완성된다.

## 현재 상태

```text
단계    Phase C 방 인식 구현 완료 (TASK-017~022). TASK-022 재미 검증(사람 플레이 관찰) 대기 — 통과 전 Phase D 금지
범위    수직 슬라이스 — 90~120 분
월드    128 × 64 × 128 복셀 섬 1 개
블록    22 종
방      5 종 (빈 방 / 창고 / 침실 / 주방 / 식당)
주민    3 명 시작 → 최대 5 명
레벨    마을 레벨 1 → 3
습격    2 회
```

[전체 로드맵](docs/project/ROADMAP.md)에 단계별 결과와 MVP 이후의 조건부 확장 계획을,
[세부 계획](docs/project/TASKS.md)에 55개 Task의 순서·의존·완료 조건을 정리했다.
Phase A·B는 완료했고 Phase C는 구현을 마쳐 분기점 1 관찰을 기다린다. 남은 미결정 정책은 TASKS 2.5의 기한에 맞춰 구현 전에 확정한다.

## 확장 원칙

**MVP는 주민 최대 5명, 아키텍처는 주민 100명과 대형 월드로 확장 가능한 구조를 목표로 한다.**
현재 128 × 64 × 128 섬은 콘텐츠 설정이다. 주민 수와 월드 크기를 고정한 로직을 피하고,
청크 단위 처리·작업 예산·게임과 렌더의 분리로 확장 경계를 확보한다.
확장 규모의 실제 성능은 별도로 측정한다. 설계 기준은 ARCHITECTURE 2.3과 ADR 017에 있다.

장기에는 약 50~100명이 생활하는 큰 마을과 외곽의 숲·광산·농업지대·해안을 목표로 한다.
사건 기반 Job Queue, 인덱스 조회, 다중 갱신 주기, Simulation LOD, 계층 경로와
Chunk Streaming을 수용할 경계를 확보한다 (ADR 018). 모두 MVP에 구현하는 것은 아니다.
첫 취침 검증 뒤 TASK-PERF-001, 역할 시스템 연결 뒤 TASK-PERF-002로 구조를 조기에 점검한다.

## 기술 스택

```text
Node.js 24 LTS  /  pnpm
TypeScript 5.x (strict)
three 0.18x  —  WebGLRenderer (WebGL2)
Vite 8.x  —  SPA. React / Next.js 를 사용하지 않는다
Vitest 4.1 이상 4.x
Web Worker (청크 그리디 메싱)
```

버전의 정본은 `package.json` 과 `pnpm-lock.yaml` 이다.
문서는 선택할 버전 계열과 최소 제약을 규정한다. 실제 설치·호환성 검증은 TASK-001에서 한다.

**Web-first, not Browser-only.** MVP는 Desktop Web Browser이며, 장기에는 공통
Game Core를 Browser와 Desktop/Steam build에서 사용하는 방향을 둔다.
wrapper는 미선정이다. 대형 에셋은 AssetManager/AssetStore 경계로 필요한 팩만
로드·캐시하고 저장 위치를 게임 로직에서 분리한다 (ADR 019).
현재 WebGL2를 유지하고 WebGPU는 실제 GPU 병목 측정 이후에만 검토한다.

### 게임 규칙은 렌더 엔진을 모른다

```text
src/game/**     three 를 import 하지 않는다. 순수 TypeScript
src/render/**   three 를 import 한다. 게임 상태를 읽어서 그리기만 한다
src/ui/**       DOM 만 쓴다
src/workers/**  순수 함수만 실행한다
```

TASK-001에서 ESLint로 강제한다. 엔진 선택은 설계 단계에서 Phaser 3 → three로 바뀌었다.
엔진 경계의 필요성을 확인한 사례이며 실제 코드 이전 비용을 검증한 것은 아니다.

`docs/research/` 는 정본이 아니라 근거다.

문서 역할·과거 기록의 적용 범위와 이번 검토는 [문서 안내](docs/README.md)에서 확인한다.
에이전트 작업 규약은 `AGENTS.md` 에 있다.

### 주요 ADR

```text
011  2D Phaser 3 를 버리고 3D 복셀 Three.js 로 전환한다
012  Prefab 배치를 버리고 자유 건축 + 방 인식을 사용한다
013  감사 포인트와 마을 레벨을 도입하되 파생 지표와 축을 분리한다
014  복셀 월드를 청크 16³ 와 그리디 메싱으로 표현한다
015  3D 복셀 통행 그래프를 쓰고, 몬스터가 블록을 파괴할 수 있게 한다
016  검토 결과를 반영해 공간·진행·저장 계약과 검증 순서를 보완한다
017  MVP 5명과 주민 100명·대형 월드의 확장 아키텍처를 구분한다
018  사건 기반 작업·다중 주기·Simulation LOD·계층 경로와 조기 성능 검증
019  Web-first, not Browser-only와 대형 에셋 입출력 경계
020  진행 안내·블록 편집·저장의 일관된 실행 계약
```

폐기된 결정(001 / 002 / 005 / 009)도 삭제하지 않고 남겨 둔다.
그 결정이 왜 옳았고 언제부터 틀렸는지가 기록이다.

## 개발

```bash
pnpm install
pnpm dev      # 개발 서버
pnpm test     # Vitest
pnpm build    # 프로덕션 빌드
```

아직 package.json과 구현 코드가 없으므로 위 명령은 TASK-001 이후 사용한다.
실행 순서는 TASKS.md 2.3을 따른다. 027과 039를 앞당기고 033은 농사·요리 전에 검증한다.
게임 로직은 three와 분리하며 테스트는 렌더러 없이 실행한다.

가장 많이 작성될 테스트는 **방 인식** 이다.
`tests/helpers/buildTestWorld.ts` 로 문자열 레이어에서 방을 그려 검증한다.

## 두 개의 검증 지점

```text
TASK-022   방을 만들고 인식시키는 과정이 즐거운가
TASK-033   밤에 주민이 내가 만든 방으로 걸어 들어가는 것이 만족스러운가
```

둘 중 하나라도 부정적이면 다음 Phase 로 넘어가지 않는다.
**콘텐츠를 추가해서 해결하려 하지 않는다.**
감성 축이 실패해도 “그래픽은 나중”으로 미루지 않고 기존 팔레트·조명·가구·주민 표현을 개선한다.

## 성공 기준

기능의 개수가 아니다.

플레이어가 아름답게 가꾼 공간에서 정감 있는 주민이 잠들고,
아침에 일어나 다시 하루를 살아가는 모습을 보면서

> 이 사람들이 사는 마을을 더 아름답게 가꾸고 싶다.

라고 생각하게 만드는 것이다.

장기에는 저녁이 온 큰 마을의 집·식당·작업장에 불이 켜지고, 수십 명이 길을 따라
귀가하거나 먹고 일하는 모습을 높은 곳에서 바라보며 **“이 마을을 조금 더 키우고 싶다.”**
라고 느끼게 한다. MVP의 작은 장면은 이 목표를 검증하는 시작점이다.
