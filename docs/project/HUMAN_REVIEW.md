## 1. 목적과 운영 원칙

사람이 실제 화면을 보고 판단해야 하는 확인은 개발 환경 밖에서 이루어지므로 즉시 받기 어렵다.
이 문서에 모아 두고, **일반 Task는 에이전트 검증(자동 테스트·headless 브라우저 관찰·계측)으로
완료한 뒤 다음 Task로 진행한다.** 사람의 확인은 모아서 한 번에 받는다.

- 완료 조건·수치의 정본은 계속 TASKS / MVP_SPEC이다. 이 문서는 새 규칙을 만들지 않는다.
- 에이전트의 관찰을 사람의 판단으로 기록하지 않는다. 각 항목은 확인 전까지 `대기`다.
- 확인 결과가 부정적이면 해당 Task를 `수정 필요`로 되돌리고 docs/state에 원인과 수정을 남긴다.
- **예외: TASK-022와 TASK-033의 재미 검증은 이 목록으로 미루고 진행할 수 없다** (AGENTS 8,
  TASKS 4). 두 지점에 도달하면 사람의 플레이 관찰을 받을 때까지 다음 Phase로 넘어가지 않는다.
  에이전트는 그 전에 관찰용 빌드·장면·질문지를 준비해 둔다.

## 2. 확인 방법

확인자는 **자기 환경에서** 저장소를 clone해 직접 실행한다. 에이전트는 확인자용 서버를 띄우지 않는다
(에이전트의 headless 자동 관찰용 임시 서버는 별개다).

```text
git clone https://github.com/seniya/game-town-builder.git && cd game-town-builder
pnpm install
pnpm dev                       → http://localhost:5173/
실제 창의 Chrome, 창 크기 1280 × 720 권장, 브라우저 확대 100 %
```

항목마다 장면 URL과 볼 것을 적었다. 결과는 아래 표의 `결과` 칸에 날짜·확인자·한두 문장으로
적고, 부정적이면 무엇이 어색했는지 구체 장면을 남긴다.

### 2.1 오너 확인판 (보기 쉬운 사본)

이 문서를 카드 형태로 보여 주는 페이지다: <https://claude.ai/artifact/7F7dRDragvhcFEaHZZ1z6z>
(비공개, 오너 계정에서 열림). 장면 주소를 누르면 확인자가 적은 실행 주소(기본
`http://localhost:5173`)로 새 탭이 열리고, 항목마다 **좋음 / 고칠 곳 있음 / 애매**와 메모를 저장할 수 있다.

- 정본은 계속 이 문서다. 확인판은 `node tools/human-review/build.mjs` 로 이 문서에서 다시 만든다
  (출력 `.review/human-review.html`, git 에 넣지 않는다).
- 에이전트는 이 문서의 항목을 바꾸면 확인판을 다시 만들어 같은 URL 에 재게시한다.
- 오너가 저장한 판단은 확인판의 공유 저장소 `results/<HR-ID>` 문서(`verdict`: good·bad·unsure,
  `note`, `updatedAt`)에 쌓인다. 에이전트가 이를 읽어 위 `결과` 칸과 상태로 옮기고, `bad` 는
  해당 Task 를 `수정 필요`로 되돌려 수정한다. 옮긴 뒤에도 저장소 기록은 지우지 않는다.

## 4. 재미 검증 게이트 — 이 목록으로 미루지 않는다

아래는 일반 대기 항목과 다르다. **사람의 플레이 관찰 결과를 받을 때까지 다음 Phase 로 넘어가지 않는다**
(AGENTS 8, TASKS 2.1 / 4). 에이전트가 관찰용 빌드·장면·질문지를 준비해 두었다.

### G1. TASK-022 방 만들기 (Phase C → D 분기점) — 상태: **통과** (2026-09-23, [기록](../state/2026-09-23_1400-task-022-gate-g1-passed.md))

준비된 빌드: `main` 의 Phase C 기록 커밋. 확인자 환경에서 2장대로 clone 후 `pnpm install && pnpm dev` → Chrome 실제 창 1280 × 720 권장, 소리 켜기.

플레이 순서(약 20~30 분). 디버그(F3)는 켜지 않는다. 진행이 막힐 때만 관찰자가 알려 준다.

```text
1  /?scene=room-lab          넓은 풀밭. 방 재료가 인벤토리에 있다(판자·문·침대·가구·창문·횃불)
   조작: 캔버스 클릭 → WASD / 마우스 / 좌클릭 파괴 / 우클릭 설치 / 1~9 선택 / E 인벤토리 / Tab 방 진단
2  가운데 빈 땅에 5 × 5 방을 직접 짓는다 (Test 2: 바닥 → 벽 두 칸 → Tab → 문 → 침대 → 벽 부수기 → 복구)
3  북쪽 줄의 사례를 Tab 으로 본다 (서쪽부터)
     A 완성된 빈 방  /  B 문 없는 방  /  C 벽 한 칸 빠진 방(서쪽 벽)  /  D 흙벽 공간
   C 는 표시만 보고 구멍을 찾아 막아 본다 (Test 3)
4  남쪽 줄의 사례를 Tab 으로 본다
     E 침대 + 화덕·물통(주방이 우선) / F 벽 한 칸의 둘째 층 빠짐 / G 방 안 1 칸 높이 판자 단(같은 높이 제한)
5  원하면 기존 블록·가구로 방을 더 꾸민다 (창문·횃불·돌벽돌·식탁과 의자). 시간 제한 없음
6  (선택) / 섬에서 처음부터 나무 → 판자 → 방 한 칸
```

질문지 — 각 질문에 예/아니오/애매 + 그렇게 느낀 구체적인 장면을 적는다.

Q8  작은 방의 실루엣·블록 팔레트·가구 배치 중 무엇이 좋았고 무엇이 아쉬웠는가. 더 꾸미고 싶었던 이유
