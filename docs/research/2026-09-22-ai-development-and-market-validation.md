# AI 중심 개발과 수익 가능성 검토

Date: 2026-09-22
Status: 상담용 검토. 구현 가능성·판매량의 실증 결과가 아니다.

## 질문과 프로젝트 현황

사용자는 바이브코딩으로 프로젝트를 잘 만들어 수익을 낼 수 있는지 물었다.
GAME_DESIGN → MVP_SPEC → ARCHITECTURE → TASKS 순서로 확인했다.
현재 저장소에는 게임 실행 코드와 package.json이 없으며 구현 전 설계 단계다.
MVP는 주민 최대 5명, 고정 섬, 90~120분 수직 슬라이스다.
100명과 대형 월드는 확장 경계이며 현재 콘텐츠 완료 조건이 아니다.

## 판단과 제안 — 프로젝트 문서에 대한 해석

- AI가 코드 작성을 주로 담당하고 사람이 범위·플레이·품질을 판단하는 방식은
  시도할 만하다. 실행 결과를 검토하지 않는 자동 개발로 상용 완성을 보장할 수는 없다.
- 어려움은 복셀 편집 이후 방·경로·시설 예약·저장이 함께 일관성을 유지하는 데 있다.
  작은 Task, 테스트, 브라우저 확인, 회귀 점검을 유지해야 한다.
- TASK-022의 건축과 TASK-033의 귀가·취침에서 재미와 감성을 먼저 확인한다.
  아름다운 공간, 주민 실루엣·동작, 카메라와 입력의 감각은 실제 플레이로 판단한다.
- 초기에는 장르를 좋아하는 외부 플레이어 5~10명 정도의 관찰을 제안한다.
  이는 통계적 시장 검증이나 새로운 Acceptance Criteria가 아니다.
  설명 없이 방을 만들 수 있는지, 자발적으로 꾸미는지, 다시 플레이하는지 관찰한다.
- 이후 배포 후보로 무료 데모와 유료 본편을 검토할 수 있다. 현재 브라우저 MVP와
  TASK 실행 순서를 유지하며 Steam 배포·wrapper·가격을 이번에 확정하지 않는다.
- 희망 수익을 매출/비용 차감 후 수익, 목표 기간으로 구체화해야 한다.
  목표 회수액과 개발·출시 비용을 판매 한 장당 예상 순수입으로 나누어 필요한
  판매량을 시나리오로 계산할 수 있지만, 현재는 입력과 수요 근거가 없다.

## 외부에서 확인한 사실

1. [Steam Playtest 공식 문서](https://partner.steamgames.com/doc/features/playtest)
   - 본편과 연결된 별도 앱으로 테스트를 운영할 수 있다.
   - 본편 상점에서 참가 신청을 받고 본편 위시리스트와 연결할 수 있다.
   - Playtest 기능과 참가 자체는 무료이며 참가권을 판매하는 기능이 아니다.
2. [Steam Demos 공식 문서](https://partner.steamgames.com/doc/store/application/demos)
   - 데모는 본편과 연결한다. 별도 데모 상점 페이지는 선택 사항이다.
   - 데모 페이지와 라이브러리에서 본편 상점으로 이동하는 링크를 제공한다.
   - 본편 출시 전 데모를 배포하려면 본편의 출시 예정 상점 페이지를 준비한다.

이 사실들은 추후 플레이 검증과 구매 관심 확인의 경로가 존재함을 뒷받침한다.
위시리스트·데모 이용이 실제 구매를 보장한다는 근거로 사용하지 않는다.

## 신뢰도와 미확인 사항

- 플랫폼 기능 설명은 운영사 1차 자료로 신뢰도가 높다. 실제 배포 시 다시 확인한다.
- AI 개발 가능성 평가는 설계 복잡도에 대한 판단이다. 이 프로젝트의 완성 사례나
  실측 생산성 연구로 입증된 결론이 아니다.
- 플레이 재미, 시각 품질, 100명 성능, 개발 기간, 경쟁작 수요, 적정 가격,
  판매량과 구매 전환율은 확인하지 않았다.
- 사용자 개발 경험, 투입 시간, 예산, 목표 수익이 없어 일정과 수익을 예측하지 않는다.
- 신규 기술 결정이 없으므로 ADR과 정본 명세를 변경하지 않는다.
