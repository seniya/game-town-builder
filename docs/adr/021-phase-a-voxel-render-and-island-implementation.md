# ADR 021. Phase A의 복셀 렌더·메싱·고정 섬 구현 방식

Status: Accepted
Date: 2026-09-23
Basis: TASK-001~008·027 구현과 단위 테스트, headless Chrome(ANGLE Vulkan, GTX 1070) 관찰. 새 외부 조사 없음.
Related: ADR 011 / 014 / 017 / 019
Amends: 없음. ADR 014의 청크·그리디 메싱 결정을 구현 수준에서 구체화한다.

## 배경

ADR 014는 16³ 청크, Worker 그리디 메싱, 18³ padded 뷰를 정했다. 구현하면서 명세가
정하지 않은 선택이 필요했다.

- 그리디 병합과 정점 AO를 함께 쓰면 AO가 다른 면을 합칠 때 음영이 보간으로 번진다.
- 아틀라스 1장과 병합 쿼드를 함께 쓰려면 쿼드 안에서 타일을 반복해야 한다.
  three의 기본 재질은 병합 쿼드의 타일 반복과 정점 AO 속성을 그대로 지원하지 않는다.
- Worker 결과는 순서가 보장되지 않고, 오래된 결과가 최신 편집을 덮으면 안 된다.
- MVP_SPEC 7.1은 절차적 생성을 금지하고 "고정 데이터"를 요구하지만 섬 형상을 좌표 목록으로
  주지 않았다. 128 × 128 높이맵을 손으로 쓰는 것은 수정·검토가 어렵다.

## 결정

1. **균일 AO 면만 병합한다.** 같은 블록이면서 네 모서리 AO 값이 모두 같은 면끼리만 그리디
   병합한다. 병합되지 않는 면도 정점 AO를 가진다. AO 이방성은 0fps 방식으로 대각선을 고른다.
2. **복셀 재질은 materials.ts의 ShaderMaterial 하나로 만든다.** 속성은 position / normal /
   uv(쿼드 로컬 반복 좌표) / ao / tile(= blockId × 3 + 면 종류)이다. 셰이더가 `fract(uv)`로
   타일을 반복하고 반구광 + 방향광 + 면 방향 음영 + AO 곡선을 계산한다. 광원 값은 Renderer의
   three 광원 객체에서 uniform으로 옮겨 한 곳에서만 정한다. 불투명·반투명 두 재질이 uniform을
   공유한다. 아틀라스는 코드로 결정적으로 그린 16px 타일(열 = 면 종류, 행 = 블록 id)이며
   최근접 필터·밉맵 없음이다.
3. **메싱 순서 규칙을 three 없는 MeshJobQueue로 분리한다.** 청크당 진행 작업은 하나다.
   결과 revision이 현재와 다르면 버리고, 업로드 직전에도 다시 확인한다. 버린 청크는 VoxelWorld의
   dirty 표시로 다시 들어오므로 큐가 재등록하지 않는다. Worker 파일은 배선만 한다.
4. **섬은 손으로 정한 계수의 결정적 식으로 만든다.** 해안선 조화 계수, 언덕(중심·반지름·높이),
   나무 24 그루·폐허 세 곳의 좌표를 island.ts의 고정 데이터로 두고 매번 같은 식으로 계산한다.
   난수·노이즈·시드를 쓰지 않는다. 이는 MVP_SPEC 7.1의 고정 섬이며 절차적 지형 생성이 아니다.

## 검토한 대안

- **AO 무관 병합**: 쿼드 수가 가장 적지만(작은 집 조각 29 쿼드) 모서리 음영이 넓게 번진다.
  공간의 입체감이 GAME_DESIGN 14의 목표이므로 택하지 않았다. 균일 AO 병합은 79 쿼드였다.
- **MeshLambertMaterial + onBeforeCompile**: 재질 수정 코드가 셰이더 청크 내부 구조에 묶이고
  WebGPU 전환 시 다시 써야 한다. ShaderMaterial 하나가 전환 범위를 더 좁힌다.
- **병합 없는 면별 쿼드 + 아틀라스 UV**: 셰이더 반복이 필요 없지만 쿼드 수가 3배 이상이다.
- **결과 도착 순서대로 표시 + 재등록**: 역순 도착 시 오래된 메시가 보이거나 중복 작업이 생긴다.
- **높이맵 배열 리터럴**: 16,384개 값을 문서처럼 검토하기 어렵고 영역 조정이 번거롭다.

## 예상되는 결과

- 매 프레임 편집이 계속되면 해당 청크는 편집이 멈출 때까지 새 메시를 올리지 못한다
  (60 edits/s 시험에서 결과 대부분 폐기, 프레임은 16.8ms 유지). 사람의 설치 속도에서는
  문제가 없었다. 연속 편집 체감은 TASK-013 이후 실제 조작으로 다시 확인한다.
- 초기 섬은 업로드 예산 프레임당 2개 때문에 256 청크가 약 2.2초에 걸쳐 나타난다.
  로드 시간 목표 5초 안이지만 첫 화면의 순서(가까운 청크 먼저)는 필요 시 개선 후보다.
- 월드 경계 밖을 air로 두므로 바다의 바깥 옆면이 보인다. 플레이 시점에서는 안개로 가려지며
  원경 표현은 TASK-034 / PERF-001에서 다시 본다.
- 셰이더 조명은 낮의 고정값이다. 낮밤 보간은 TASK-034에서 같은 uniform을 갱신한다.
- 섬 형상을 바꿀 때는 island.ts의 계수만 고치고 island 테스트(총량·영역·스폰·후보)를 갱신한다.
