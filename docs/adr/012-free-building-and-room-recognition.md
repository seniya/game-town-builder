# ADR 012. Prefab 배치를 버리고 자유 복셀 건축 + 방 인식을 사용한다

Status: Accepted
Date: 2026-09-22
Supersedes: ADR 002

## 배경

ADR 002 는 Prefab Building Placement 를 선택했다.

```text
Farm     3 × 3
Kitchen  2 × 2
House    4 × 4
Barrier  1 × 1
```

그 ADR 은 자신의 약점을 이미 기록해 두었다.

> 플레이어의 표현 자유도가 낮다.
> 마을을 "내 마을" 로 느끼는 애착이 건축 자유도에서 오는 게임과 비교해 약할 수 있다.

프로젝트 목표가 DQB2 로 재정의되면서 이 약점이 치명적인 것이 되었다.

DQB2 에서 플레이어가 느끼는 감정은 다음과 같다.

```text
Prefab      게임이 준 것을 놓았더니 주민이 쓴다
자유 건축    내가 설계한 공간을 게임이 알아보고, 주민이 쓴다
```

두 번째 문장의 "게임이 알아보고" 가 DQB2 의 심장이다.

이것을 **방 인식 (Room Recognition)** 이라고 부른다.

## 결정

**1. 모든 건축은 블록 단위 자유 건축이다.**

건물이라는 배치 단위를 없앤다. 플레이어는 블록을 놓고 부순다.

```text
BuildingSystem       삭제
BuildingConfig       삭제
BuildValidator       삭제
Prefab 4 종          삭제
Ghost Preview        블록 1 칸 하이라이트로 대체
```

**2. 방은 규칙으로 인식한다. 플레이어가 선언하지 않는다.**

플레이어는 "여기를 침실로 지정" 하는 UI 를 쓰지 않는다.
공간을 만들면 게임이 판정한다.

**3. 빈 방 조건**

다음을 모두 만족하면 `EmptyRoom` 으로 인식한다.

```text
바닥         내부 셀 아래(y-1)가 전부 고체 블록이다
내부 공간     연결된 공기 셀 집합이다
벽           내부 집합의 수평 경계가 전부 벽 블록 또는 문이다
벽 높이       경계 블록이 바닥 위 2 칸 이상 연속으로 존재한다
문           경계에 Door 블록이 1 개 이상 있다
천장         필요하지 않다
최대 크기      바닥 면적 <= roomMaxFloorArea
```

천장을 요구하지 않는 것은 DQB2 와 같다.
실내 조명과 비 연출은 천장 유무와 무관하게 "방 안" 여부로 판정한다.

**4. 방 타입은 가구 집합으로 판정한다.**

빈 방 안에 놓인 가구 블록의 집합을 구하고, 방 레시피 목록과 대조한다.

```text
RoomRecipe {
  id
  priority
  requires: { blockId, count }[]
  grants:   주민 행동에 필요한 지점 (침대 / 조리대 / 식탁 ...)
}
```

여러 레시피를 만족하면 `priority` 가 높은 것을 채택한다.
어느 것도 만족하지 못하면 `EmptyRoom` 으로 남는다.

**5. 배치의 논리성을 판정에 포함한다.**

DQB2 는 "음식은 테이블 위에, 의자는 테이블 옆에" 를 요구한다.
같은 원칙을 쓴다. 개수만 세지 않는다.

```text
adjacency 조건    의자는 테이블과 수평 인접이어야 한다
surface 조건      음식은 테이블 블록 바로 위에 있어야 한다
access 조건       침대는 최소 한 면이 통행 가능한 셀에 접해야 한다
```

`access` 조건이 없으면 주민이 도달할 수 없는 가구가 방 판정을 통과한다.

**6. 재판정은 변경된 영역만 수행한다.**

블록이 놓이거나 부서지면 그 좌표가 속한 방, 그리고 인접한 미판정 공간만
다시 판정한다. 월드 전체를 매 프레임 스캔하지 않는다.

## 방 인식 알고리즘

```text
1. 변경된 블록 좌표에서 Door 블록을 후보로 모은다
2. 각 Door 의 양쪽 수평 인접 셀 중 공기인 셀을 flood fill 시작점으로 잡는다
3. 시작점의 y 를 바닥 위 첫 칸으로 고정하고 4 방향 flood fill 한다
   - 공기 셀이면 확장한다
   - 벽 또는 문이면 경계로 기록하고 멈춘다
   - 아무것도 없으면 (열린 하늘 / 지면 낭떠러지) 실패로 종료한다
   - 방문 셀이 roomMaxFloorArea 를 넘으면 실패로 종료한다
4. 성공하면 내부 셀 집합 · 경계 집합 · 문 집합이 확정된다
5. 각 경계 셀의 y+1 이 고체인지 검사한다 (벽 높이 2)
6. 내부 셀 범위 안의 가구 블록을 수집한다
7. RoomRecipe 목록을 priority 내림차순으로 대조한다
8. 최초로 전부 만족하는 레시피의 타입을 부여한다
```

3번의 "실패로 종료" 두 가지가 중요하다.

```text
열린 공간      벽을 다 두르지 않으면 flood fill 이 무한히 퍼진다.
              공기 셀이 월드 경계나 미탐색 청크에 닿으면 즉시 실패한다.
크기 상한      마을 전체를 벽으로 두르고 "이게 침실이다" 라고 주장하는 것을 막는다.
```

## 주민 행동과의 연결

방 판정 결과가 주민 AI 의 목적지를 만든다.

```text
Bedroom    bed 블록 위치 목록        →  SleepAction 목적지
Kitchen    cookingStation 위치       →  CookAction 목적지
DiningRoom table 인접 chair 위치     →  EatAction 목적지
Storeroom  chest 위치               →  마을 저장소 물리적 위치
```

이전 구조의 `findNearestBuilding(type)` 은 `findNearestRoom(type)` 이 된다.

`findNearestBuilding` 이 한 줄이었던 것은 Prefab 이 침대 위치를 상수로 알고 있었기
때문이다. 이제는 방 판정 결과가 그 정보를 들고 있어야 한다.
방 인식의 출력에 **주민이 쓸 지점 목록** 을 반드시 포함시키는 이유가 이것이다.

## 검토한 대안

**A. Prefab 유지 + 외관만 커스터마이즈**

건물의 기능은 Prefab 이 정하고 플레이어는 벽지와 지붕만 고른다.

문제는 "게임이 내 설계를 알아봤다" 는 감정이 발생하지 않는 것이다.
DQB2 와 같아지려는 목표에 정면으로 어긋난다.

**B. 구역 지정 방식 (RimWorld / Stardew 스타일)**

플레이어가 드래그로 영역을 지정하고 역할을 부여한다.

자유 건축보다 구현이 가볍고 판정이 결정적이다.

그러나 판정의 주체가 플레이어다. 게임이 알아보는 것이 아니라
플레이어가 선언하는 것이다. 인식 루프가 성립하지 않는다.

MVP 이후 "이 공간이 왜 방으로 인식되지 않는가" 를 알려주는
**진단 UI** 의 형태로 일부 아이디어를 가져온다.

**C. 방 판정을 매 프레임 월드 전체에 수행한다**

구현이 단순하다.

128 × 64 × 128 월드에서 flood fill 을 전역으로 돌리면 프레임 예산을 초과한다.
변경 영역 기반 갱신이 필수다.

**D. 천장을 요구한다**

물리적으로 자연스럽다.

그러나 플레이어가 방을 만들고도 인식되지 않는 가장 흔한 원인이 된다.
DQB2 가 천장을 요구하지 않는 것은 이 좌절을 피하기 위한 설계로 보인다.
같은 선택을 한다.

## 예상되는 결과

긍정적:

- 플레이어가 만든 공간이 인식되는 순간이 게임의 핵심 감정 지점이 된다.
- 같은 침실을 두 플레이어가 전혀 다르게 만들 수 있다. 애착이 생긴다.
- 가구가 게임 콘텐츠가 된다. 새 가구 = 새 방 = 새 주민 행동으로 확장이 자연스럽다.

부정적 / 위험:

- **판정이 실패했을 때 플레이어가 이유를 모르면 게임이 망가진다.**
  "왜 방이 아닌가" 를 알려주는 진단 UI 를 선택 기능이 아니라 필수로 둔다.
- 방 판정과 주민 행동 사이의 연결이 이전보다 훨씬 복잡하다.
  침대가 사라지면 자고 있던 주민이 어떻게 되는지 같은 경우를 전부 정의해야 한다.
- 성능. 건축 중에는 블록 변경이 연속으로 발생한다.
  재판정을 프레임당 예산 안에서 큐로 처리해야 한다.
- 플레이어가 벽을 한 칸 부수면 방이 해제된다.
  주민이 사용 중인 방이 해제되는 경우의 동작을 정의해야 한다.
