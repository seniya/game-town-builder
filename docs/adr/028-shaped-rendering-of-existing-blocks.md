# ADR 028. 기존 블록의 비정육면체 모양 표현 — 범위와 시점

Status: Accepted (범위·시점). 구현 방식의 세부는 TASK-SHAPE-001 착수 전에 이 ADR 을 보완한다
Date: 2026-09-24
Basis: 사용자 의견("DQB2 는 모든 블록이 정사각형 모양이 아니다. 이를 구현해야 오브젝트의 미적 완성도가 높아진다"), 시점 결정(선택지 b). ADR 026(침대·문 모형) 경험.
Related: ADR 011 / 021 / 026
Amends: MVP_SPEC 31(표현), TASKS 2.3(실행 순서), ROADMAP E

## 배경

모든 블록이 1 칸 정육면체로 그려진다. G2 에서 침대·문은 렌더 모형으로 바꿨고(ADR 026) 확인자가 자연스럽다고 했다(HR-010).
나머지 가구·소품도 상자라서 공간을 꾸미는 즐거움(GAME_DESIGN, TASK-022 감성 축)이 모양에서 막힌다.

## 결정

1. **범위는 기존 블록의 모양만.** torch / window / table / chair / chest / cooking_stove / water_pot / crop / bell 이 후보다.
   새 블록 종류(반 블록·계단·울타리 등)는 MVP_SPEC 38 에 따라 만들지 않고 MVP 이후 확장 후보로 둔다.
2. **게임 규칙은 그대로.** 충돌·통행·방 판정·설치·드롭은 blocks 의 기존 필드를 쓴다. 모양은 렌더 표현이다(ADR 026 과 같은 원칙).
3. **시점은 Phase E 의 TASK-032(식사) 뒤, TASK-039 앞.** 요리·식사가 붙어 화덕·식탁·의자가 주민의 사용 장면이 된 다음, 모양과 사용 자세(앉기·조리)를 함께 맞춘다.
4. **방식은 착수 전에 정한다.** 기본 방향: 정적인 모양은 청크 메셔의 "블록 → 상자 목록" 모양 표로 그리고(드로우콜을 늘리지 않는다), 움직이는 것(문)은 모형으로 둔다.
   메셔 성능(TASK-005 / 006 기준)과 AO·면 컬링 규칙을 착수 전에 이 ADR 에 보완한다.

## 검토한 대안

- **지금(PERF-001 전) 구현**: 가구 사용 장면이 아직 없어 모양과 자세를 두 번 맞추게 된다.
- **MVP 이후로 미루기**: 공간을 가꾸는 즐거움이 MVP 검증의 핵심인데, 053 통합 검증까지 상자 가구로 보게 된다.
- **모든 모양을 렌더 모형(PropView)으로**: 가구 수만큼 객체·드로우콜이 늘어 대형 마을 원칙(ADR 017)과 맞지 않는다.

## 예상되는 결과

- Phase E 의 식사 뒤에 한 Task 가 늘어난다. 콘텐츠·규칙은 늘지 않는다.
- 조준 테두리·파괴 균열은 1 칸 상자 기준으로 남을 수 있다. 착수 때 함께 검토한다.
