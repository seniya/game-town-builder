# ADR 025. Phase D의 통행·경로·NPC 판단·취침 배정·낮밤 구현 방식

Status: Accepted
Date: 2026-09-23
Basis: TASK-023~026·028·029·034와 TASK-033 구현, 단위 테스트(신규 60여 개), headless Chrome 148 관찰·계측. 새 외부 조사 없음.
Related: ADR 006 / 008 / 015 / 017 / 018 / 024
Amends: ARCHITECTURE 2.1(ActionView), 11.1 / 11.3(탐색 토큰·스케줄러·cells 목표), 11.4, 13.4, 14(ActionPlan), 15. MVP_SPEC 9.5(NPC 물 통행), 19.2(폭), 20.2(배속 범위).
방 판정 조건은 바꾸지 않았다. 새 블록·가구·자원·메커닉을 추가하지 않았다.

## 배경

Phase D 는 주민이 처음으로 걷고 판단하는 단계다. 명세가 정하지 않았거나 구현에서 선택이 필요했던 지점:

- NPC·몬스터가 물에 들어갈 수 있는가(MVP_SPEC 9.5 가 TASK-024 에 넘겼다).
- ARCHITECTURE 11.3 은 "입력 search 는 변경하지 않고 다음 상태를 반환"한다고 했다. 그대로면 이어 탐색할 때마다 open/closed 전체를 복사한다.
- 침대 approachCells 가 여러 개인데 PathGoal 은 칸 하나 또는 반경뿐이다.
- `decideAction(ctx): Action | null` 은 아직 없는 Action(식사·역할·도피·대화)의 판단을 테스트할 수 없게 한다.
- entities 는 types / data 만 의존하는데 NPC.action 은 실행 가능한 Action 이다.
- "실제 경로가 있는 빈 침대를 배정"(MVP_SPEC 18.1)의 "실제 경로"를 언제 확인하는가.
- 복셀 셰이더가 사용자 정의 ShaderMaterial 이라 three 의 점광원이 지형에 닿지 않는다.

## 결정

1. **통행**: `isStandable` = 공통 `isStandableCell` + 발·머리 칸이 물 아님. 방 판정은 공통 함수만 쓴다(물에 잠긴 접근 셀은 실제 경로 실패로 드러난다).
   이웃은 4 방향 × 같은 높이 / +1 / −1, +1 은 출발 칸 y+2, −1 은 도착 열의 출발 높이 +1 칸이 통행 가능해야 한다.
   캐시는 (칸, actor) 이웃 목록이고 읽은 모든 칸의 역참조를 둔다. 경로 감시(`watch`)도 같은 칸 집합(`stepReadCells`)을 쓴다.
   칸 키는 수치(`navKey`)다. 블록 변경 알림을 받는 즉시 무효화한다.
2. **탐색 상태는 한 번만 이어 쓰는 불투명 토큰**이다. 이어 쓰면 넘긴 토큰은 소비된다(재사용하면 예외). 토큰은 from/goal/actor/revision/
   확장 범위만 공개한다. 숨은 전역 상태가 없다는 원칙은 그대로다.
3. **PathScheduler**(update 6 번)가 요청 핸들과 continuation 을 소유한다. 프레임 예산 4000 을 대기 요청 수로 나누고 남은 몫은 뒤로 넘기며
   끝나지 않은 요청은 큐 뒤로 간다. 변경 칸이 세션의 확장 범위 ±2 안일 때만 그 세션을 다시 시작한다.
4. **PathGoal 에 `cells`** 를 더한다(여러 접근 셀 중 하나). 휴리스틱은 max(|dx|+|dz|, |dy|) 의 최솟값이다.
5. **이동**: MovementController 는 플레이어와 같은 충돌·중력·step-up 을 쓴다. 캐릭터끼리는 충돌하지 않는다. 재계산은 무효화·연속 blocked 3 회에서
   요청하고 0.5 초 간격을 지킨다. MoveAction 은 요청 중 제자리에 선다.
6. **판단은 `ActionPlan`** 을 반환한다(순수 데이터 + key). NPCSystem 이 Action 으로 만들고 start / cancel 을 한 번씩 보장한다.
   아직 없는 Action 의 계획은 그 사실을 적은 대기로 선다. 같은 key 면 유지하고, 이동이 진행 중이면 목적 칸에 들어섰어도 칸 가운데에서 끝날 때까지 유지한다.
   실패한 계획은 0.5 초 동안 같은 key 로 다시 시작하지 않는다(도달 불가 목적지로 매 프레임 탐색하지 않게).
7. **ActionView**: types 에 Action 의 읽기 view(kind / label / key / facilityUse(+pose) / pose / 디버그용 경로)를 두고 `NPC<A extends ActionView>` 로 쓴다.
   실행 인터페이스는 actions/Action.ts 에 있다.
8. **침대 배정**: SleepSystem 이 가까운 빈 침대 후보를 고르면 주민 칸에서 그 접근 셀까지 경로를 요청하고, 경로가 나오면 확정한다. 경로가 없으면
   그 (주민, 침대) 조합을 기억하고 다른 침대를 본다(블록·방이 바뀌면 다시 시도). 확인 중에는 배정이 없으므로 20:00 이면 광장에서 쉰다.
   침대 파괴는 방 재판정을 기다리지 않고 BLOCK_CHANGED 의 removedObject 로 즉시 푼다. SleepAction 은 매 프레임 `isAssigned` 로 확인한다.
9. **광장 칸**: 종에서 2.5 칸 둘레의 설 수 있는 칸을 각도 순으로 늘어놓고 0, 1/2, 1/4, 3/4 … 순서로 주민에게 준다(떨어져 둘러앉게).
10. **표현**: 주민 모형은 render/NpcView.ts 의 상자 조합이다. 역할별 옷·모자, 걷기(팔다리 흔들기·튀기), 정지(숨쉬기·둘러보기), 눕기(침대 두 칸 위, 머리는 anchor 쪽,
    베개·이불·z 표지), 앉기(다리 앞으로, 종을 바라봄). 게임 위치는 접근 셀에 남는다.
11. **낮밤**: 하루 키프레임(하늘·해·반사광·밤 정도)을 smoothstep 으로 보간한다. torch 칸 목록은 처음 한 번 청크를 훑고 이후 BLOCK_CHANGED 로 갱신한다.
    카메라에 가까운 torch 16 개를 복셀 셰이더 uniform 과 캐릭터용 PointLight 16 개(개수 고정, 셰이더 재컴파일 방지)에 준다. torch 를 새로 만들지 않는다.
12. **배속은 시계만** 빠르게 한다. 캐릭터 이동은 실시간이다.

## 검토한 대안

- **탐색 상태를 매번 복사하는 불변 continuation**: 4000 노드씩 이어 가는 긴 탐색에서 복사량이 매 프레임 누적된다. 예산의 의미가 없어진다.
- **변경이 있으면 모든 세션 재시작**: 플레이어가 먼 곳을 계속 편집하면 긴 탐색이 끝나지 않는다(11.3 의 "영구 재시작 루프 금지").
- **decideAction 이 Action 을 직접 생성**: 순수성은 유지되지만 없는 Action 클래스를 미리 만들어야 하고, 판단 테스트가 실행 객체에 묶인다.
- **밤에 실제 이동으로만 경로 확인**: 20:00 에 침대로 가다 실패하고 나서야 다른 침대를 찾게 되어 "배정 = 실제 경로" 조건을 늦게 지킨다. 이동 실패 보고는 보조로 남겼다.
- **NPC 가 물을 걸을 수 있게 두고 복귀 규칙 적용**: 경로가 해안 물길을 지나는 장면이 생긴다. 수영·복귀는 MVP 범위가 아니다.
- **three 기본 재질로 지형 교체(점광원 자동 적용)**: 아틀라스·AO 셰이더(ADR 021)를 버려야 한다.

## 예상되는 결과

- 주민 수가 늘어도 경로 비용은 프레임 예산 안에서 나뉜다. 100 명 부하는 PERF-001 에서 잰다.
- 식사·역할·도피·대화 Action 은 해당 Task 에서 NPCSystem 의 createAction 과 후보 포트만 채우면 된다.
- 문 블록은 주민이 지나가도 열리는 모습이 없다. TASK-033 관찰에서 거슬린다는 지적이 나오면 렌더 표현으로만 다룬다(문 규칙은 그대로).
