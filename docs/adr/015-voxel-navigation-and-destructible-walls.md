# ADR 015. 3D 복셀 통행 그래프를 쓰고, 몬스터가 블록을 파괴할 수 있게 한다

Status: Accepted — operational details amended by ADR 016
Date: 2026-09-22
Evidence: docs/research/2026-09-22-dragon-quest-builders-2.md
Supersedes: ADR 005, ADR 009

## 배경

ADR 005 는 다음을 결정했다.

```text
1. 방벽은 몬스터만 막는다 (통행 레이어 ground / monster 2 개)
2. 방벽은 파괴되지 않는다
3. 마을 입구를 정확히 한 곳, 5 타일로 고정한다
4. safetyLevel = 막힌 입구 타일 수 / 5
```

이 결정들은 전부 **Prefab 건축과 2D 타일맵** 을 전제로 한다.

ADR 012 가 자유 건축을 도입하면서 전제가 사라졌다.

```text
"마을 입구는 정확히 한 곳"     플레이어가 벽을 아무 데나 쌓으므로 정의 불가
"방벽" 이라는 건물 종류         존재하지 않는다. 벽은 그냥 블록이다
2D NavigationGrid              월드에 높이가 생겼다
"방벽은 파괴되지 않는다"        마을 전체를 두르면 방어가 영구히 해결된다
```

마지막 항목이 특히 문제다.

자유 건축에서 벽이 부서지지 않으면, 플레이어는 한 번 마을을 둘러싸는 것으로
방어라는 주제를 영원히 끝낸다. 목수 NPC 의 존재 이유도 함께 사라진다.

## 결정

**1. 통행 판정은 3D 복셀 그래프로 한다.**

캐릭터는 높이 2 칸이다.

```text
(x, y, z) 가 통행 가능한 발 위치인 조건

  block(x, y-1, z)  가 solid    발을 디딜 바닥이 있다
  block(x, y,   z)  가 비고체    발이 들어갈 공간이 있다
  block(x, y+1, z)  가 비고체    머리가 들어갈 공간이 있다
```

이동은 수평 4 방향이며, 각 방향마다 세 가지 높이를 시도한다.

```text
같은 높이   y
한 칸 오름   y+1   (머리 위 y+2 도 비어 있어야 한다)
한 칸 내림   y-1
```

두 칸 이상의 낙차는 통행 불가다. 계단을 쌓아야 한다.
NPC·몬스터의 사다리 / 점프는 MVP 범위 밖이다. 플레이어 점프는 MVP_SPEC 9장을 따른다.

`NavigationGrid` 라는 이름을 `NavigationGraph` 로 바꾼다.
격자가 아니라 조건부 그래프이기 때문이다.

**2. 통행 레이어 2 개를 없앤다.**

ADR 005 의 `isWalkable(pos, 'ground' | 'monster')` 를 삭제한다.

몬스터와 NPC 는 같은 통행 규칙을 쓴다.
차이는 통행이 아니라 **문을 대하는 태도** 로 표현한다.

```text
Door 블록
  Player / NPC   통과할 수 있다 (비고체로 취급)
  Monster        통과할 수 없다. 파괴 대상으로 취급한다
```

이 한 줄이 ADR 005 의 "플레이어는 갇히지 않는다" 를 그대로 보존한다.
플레이어는 문을 달면 되고, 몬스터는 문을 부숴야 한다.

**3. 몬스터는 블록을 파괴할 수 있다.**

ADR 005 의 "방벽은 파괴되지 않는다" 를 뒤집는다.

```text
몬스터가 종 중심 반경 안의 통행 가능한 셀로 경로를 찾는다
    ↓
경로가 있다        → 이동한다
NO_PATH          → 도달 가능 영역의 경계에서 실제 파괴 가능한 대상을 고른다
NODE_LIMIT       → 확인된 부분 경로만 이동하거나 정지 후 재탐색한다
    ↓
그 블록 앞으로 이동하여 파괴 행동을 시작한다
    ↓
blockDefinition.breakSeconds × 2.0 경과 후 블록이 공기가 된다
    ↓
통행 그래프가 국소 갱신되고 경로를 다시 찾는다
```

파괴 대상에서 제외하는 블록을 둔다.

```text
지형 블록 (흙 / 돌 / 나무 원목)   파괴 대상 아님. 우회한다
terrain=false이며 파괴 가능한 종류  파괴 대상. bell 제외
```

지형까지 파고들면 몬스터가 마을을 관통하는 터널을 뚫어 통제가 불가능해진다.

**4. 파괴된 블록은 수리한다.**

```text
플레이어   직접 다시 놓는다
목수 NPC   낮 시간에 파괴된 좌표를 찾아 자동으로 복구한다
```

목수가 복구할 수 있는 블록 수에 하루 상한을 둔다.
목수 혼자 모든 피해를 되돌리면 플레이어가 개입할 이유가 없다.

파괴된 좌표는 `DamageLog` 에 남는다. 목수의 작업 목록이자 수리 UI 의 근거다.

**5. safetyLevel 을 다시 정의한다.**

입구 타일 커버리지로는 계산할 수 없다. 자유 건축에는 정해진 입구가 없다.

```text
safetyLevel = 100 * (마을 중심에 도달하지 못한 몬스터 수) / (직전 습격의 총 몬스터 수)
```

실제 습격 결과에서 계산한다. 습격이 한 번도 없었으면 100 으로 둔다.

파생값이라는 ADR 004 의 원칙을 지키면서, 자유 건축과 무관하게 정의된다.

**"벽을 얼마나 잘 쌓았는가" 를 사전에 채점하지 않는다.**
채점하면 플레이어가 점수를 위해 벽을 쌓게 되고, 방어라는 상황이 사라진다.
결과로만 판정한다.

## 검토한 대안

**A. 3D 를 쓰되 통행은 2D 높이맵으로 근사한다**

각 (x, z) 마다 "걸을 수 있는 y" 를 하나만 저장한다.

구현이 훨씬 싸다.

문제는 이 게임이 건축 게임이라는 것이다.
2 층 집, 다리 아래 통로, 지하실이 전부 표현 불가능해진다.
DQB2 와 같아지려는 목표에 맞지 않는다.

**B. 몬스터가 지형까지 파괴할 수 있게 한다**

DQB2 에 가깝다.

문제는 복구 불가능한 피해가 누적되는 것이다.
섬의 지형이 뚫리면 되돌릴 방법이 없고, 통행 그래프가 예측 불가능해진다.
확장 후보로 남긴다.

**C. 벽을 파괴하지 않고, 몬스터가 벽을 넘어온다**

날아다니는 몬스터를 둔다.

벽을 쌓을 이유가 사라진다. 벽이 무의미한 게임이 된다.
일부 몬스터 종류로는 유효하므로 MVP 이후 다양성 확보 수단으로 남긴다.

**D. safetyLevel 을 "마을을 둘러싼 벽의 폐곡선 여부" 로 판정한다**

방 인식의 flood fill 을 마을 전체에 재사용한다.

기술적으로 가능하다.

문제는 플레이어가 미학이 아니라 판정을 위해 벽을 쌓게 된다는 것이다.
또 마을 규모가 커지면 flood fill 범위가 계속 넓어져 비용이 예측 불가능하다.

## 예상되는 결과

긍정적:

- 방어가 1 회성 과제가 아니라 반복되는 상황이 된다.
- 목수 NPC 에게 명확한 역할이 생긴다. 이전 설계에서 목수는 할 일이 빈약했다.
- 파괴 → 수리 → 더 두꺼운 벽이라는 건축 동기가 자연스럽게 발생한다.
- 통행 규칙이 하나라서 NPC / 몬스터 경로 코드를 공유한다.

부정적 / 위험:

- **진행 롤백 위험.** ADR 005 가 경계한 문제다.
  ADR 013 이 마을 레벨과 해금을 비가역으로 정의해 해결한다.
  진행 이벤트의 완료 여부도 비가역으로 둔다.
- 경로탐색 비용이 2D 보다 크다. 3 방향 높이 시도로 분기가 3 배다.
  탐색 노드 수 상한과 경로 캐시를 둔다.
- 블록 변경 시 통행 그래프 국소 무효화가 필요하다.
  발·머리·step-up 중 읽은 셀의 역참조로 캐시와 경로를 무효화한다.
- 플레이어가 자는 사이 마을이 부서져 있는 경험은 불쾌할 수 있다.
  습격당 16복셀 피해 상한과 아침 피해 보고를 적용한다 (MVP_SPEC 24~25장).
  다중 칸 객체는 전체 파괴·복원하며 피해 수와 수리량은 점유 복셀로 센다.
