# ADR 001. 게임 엔진으로 Phaser 3 을, 빌드 도구로 Vite SPA 를 사용한다

Status: Accepted
Date: 2026-09-22

## 배경

2D Top-down 마을 복구 게임의 MVP를 Desktop Web Browser에서 20~30분 플레이 가능한
수준으로 만들어야 한다.

필요한 기능은 Canvas 렌더링, Scene 관리, Sprite 애니메이션, Tilemap, 입력, 카메라,
오디오, 게임 루프다.

MVP의 목적은 기술 검증이 아니라 **"건설 → 주민 행동 변화"가 재미있는지**를 확인하는
것이므로, 엔진 자체를 만드는 데 시간을 쓸 수 없다.

## 결정

게임 엔진으로 **Phaser 3** 를 사용한다. (3.90 이상, 4.x 금지)

빌드 도구로 **Vite** 를 사용하고 **SPA** 형태로 빌드한다.

서버를 두지 않으며 게임 전체가 클라이언트에서 실행된다.

버전의 정본은 `package.json`과 `pnpm-lock.yaml`이며, 문서는 메이저 버전 제약만
규정한다. 패키지 매니저는 pnpm을 사용하고 lockfile을 커밋한다.

## 검토한 대안

**Phaser 4**

MVP 기간 중 API가 변할 가능성이 있고, 레퍼런스와 예제가 3.x에 비해 적다.
핵심 재미 검증에 새 메이저 버전의 위험을 감수할 이유가 없다.

**PixiJS + 직접 구현**

렌더링만 제공하므로 Scene, Tilemap, 입력, 오디오, 애니메이션을 직접 만들어야 한다.
MVP 일정에 맞지 않는다.

**Unity / Godot**

웹 배포 빌드가 무겁고, 문서 기반으로 AI 코딩 에이전트가 작업하기에
텍스트 소스가 아닌 씬 파일 비중이 커서 협업 비용이 높다.

**Next.js**

서버 사이드 렌더링과 라우팅이 필요하지 않다.
단일 캔버스 게임에 프레임워크 규약을 얹으면 복잡성만 늘어난다.

## 예상되는 결과

긍정적:

- Tilemap과 Scene을 바로 사용할 수 있어 개발 우선순위 1~3단계를 빠르게 통과한다.
- Vite의 빠른 HMR로 밸런스 수치를 조정하며 반복 검증할 수 있다.
- 배포물이 정적 파일이므로 인프라 비용이 없다.

부정적 / 위험:

- Phaser 4로 이전할 때 Scene과 렌더링 API 변경 비용이 발생한다.
  이를 줄이기 위해 게임 규칙을 Phaser에서 분리한다(ADR 006).
- Vite 메이저 버전과 Node 24의 호환성을 셋업 시 확인해야 한다.
