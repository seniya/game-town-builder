# ADR 046. X0 진행: 오너 위임으로 V1 선택, 최신 그래픽 렌더 파이프라인(그림자·톤 매핑·빛 번짐·하늘)

Status: Accepted
Date: 2026-09-25
Basis: 오너 지시(2026-09-25) "X0 을 최신 그래픽 느낌에 맞게 알아서 진행해보자". ADR 044(미술 방향), ADR 045(시안 제작 방식)
Related: MVP_SPEC 36·45, 확장 로드맵 X0, HUMAN_REVIEW V1·V2, AGENTS 7·8

## 배경

STYLE-001 시안 장면을 만든 뒤 게이트 V1(등신비·눈·명암·외곽선·블록 방향 선택)을 오너 확인으로 기다리고 있었다.
오너는 V1 에 답하는 대신 X0 전체를 "최신 그래픽 느낌에 맞게 알아서" 진행하라고 했다.
V1 은 AGENTS 8 의 재미 검증 게이트(TASK-022·033)가 아니라 확장 로드맵이 정한 미술 방향 게이트라 오너가 위임할 수 있다.

지금 화면은 형태(상자 사람·픽셀 노이즈 블록)만이 아니라 **렌더 방식**도 오래된 복셀 게임 같다.
그림자가 없어 사람·가구가 땅에 붙어 보이지 않고, 하늘은 단색이며, 톤 매핑·빛 번짐이 없어 밤의 불빛이 평평하다.
"최신 그래픽 느낌" 은 형태를 둥글게 하는 것만으로는 얻을 수 없다.

## 결정

1. **V1 의 선택은 에이전트가 한다.** 2.5 등신·큰 눈·툰 3 단 + 가장자리 밝힘·외곽선(사람·가구·소품만)·64 px 손그림풍 블록
   (MVP_SPEC 45.2). 이 값은 오너의 판단으로 기록하지 않는다. 오너의 확인은 **V2(전체 장면)** 에서 함께 받고,
   V2 가 부정적이면 45.2 를 다시 연다. V2 는 위임되지 않았다. X1 은 V2 통과 전에 시작하지 않는다.
2. **렌더 파이프라인을 올린다(MVP_SPEC 45.3).** three.js WebGL 그대로, three 패키지의 `examples/jsm` 모듈만 쓴다.
   - 방향광 **그림자 지도**(PCF) 1 장을 카메라가 보는 곳 주변에 둔다. 복셀 셰이더는 three 의 그림자 셰이더 조각을 그대로 쓴다.
   - 걷힌 천장은 그림자도 던지지 않도록 청크 메시의 깊이 재질이 같은 걷어 내기 규칙을 쓴다.
   - `EffectComposer` → 장면 → **빛 번짐**(UnrealBloom, 절반 해상도) → **출력**(Neutral 톤 매핑·sRGB) → **색 보정**(비네트).
     렌더 타깃은 반정밀도 부동소수·MSAA 4 이다.
   - **하늘 돔** 셰이더(그라데이션·해 광륜·구름·별)와 물·창문 불빛 셰이딩을 복셀 재질에 더한다.
   - `?quality=low` 는 그림자·빛 번짐을 끈다.
3. 순서를 바꾼다. 렌더 바탕(STYLE-005)을 먼저 해야 이후 모형·텍스처의 색을 같은 조건에서 맞출 수 있다.
   `STYLE-005(조명·하늘·후처리·재질 규약) → STYLE-004(블록) → STYLE-002(사람) → STYLE-003(가구·아이콘) → STYLE-007(UI·몬스터) → STYLE-006(측정·V2)`.
   STYLE-005 에 있던 UI·몬스터는 STYLE-007 로 나눈다.

## 검토한 대안

- **V1 을 계속 기다린다**: 오너가 명시적으로 위임했으므로 기다릴 이유가 없다. 대신 에이전트 선택을 오너 판단으로 적지 않고 V2 에서 확인받는다.
- **화면 공간 주변광 가림(SSAO·SAO·GTAO)**: 사람이 땅에 붙어 보이는 효과가 크지만 장면의 법선·깊이를 한 번 더 그려
  드로우콜이 거의 두 배가 되고(MVP_SPEC 36 의 600 미만을 그림자 패스와 함께 넘기 쉽다), 블록은 정점 AO 가 이미 있다.
  그림자 지도가 접지감을 대신한다. 성능 여유가 확인되면 X3 이후 다시 본다.
- **WebGPURenderer 와 SunLight(계단식 그림자)**: AGENTS 7 이 금지한다.
- **후처리 없이 재질만 조정**: 톤 매핑·빛 번짐 없이는 밤 불빛과 해질녘의 빛이 평평하다. 비용은 전체 화면 몇 번이라 작다.
- **실시간 그림자를 사람·가구에만(블록은 굽기)**: 블록이 편집되면 다시 구워야 하고, 해가 움직여 굽기가 맞지 않는다.

## 예상되는 결과

- 사람·가구·나무가 그림자로 땅에 붙고, 집 안팎의 빛 차이와 밤 불빛의 번짐이 생긴다. 하늘에 깊이가 생긴다.
- 드로우콜이 그림자 패스만큼 늘어난다(카메라 주변 청크·사람·가구). 사람 한 명의 드로우콜을 줄이기 위해 STYLE-002 는
  관절별 메시 대신 강체 스키닝 한 메시를 쓴다(ADR 045 의 대안 중 "스키닝 메시" 를 가중치 1 의 강체 스키닝으로 다시 채택).
- 모든 색(블록 팔레트·옷·가구)을 톤 매핑 뒤 화면 기준으로 다시 맞춰야 한다. STYLE-004 이후 작업은 이 파이프라인에서 색을 고른다.
- headless 비교 기준(드로우콜·FPS)이 바뀐다. STYLE-006 에서 36 장 조건으로 다시 잰다.
