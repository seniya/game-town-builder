# ADR 047. 가구·소품을 청크 메시의 모양 상자에서 인스턴싱 둥근 모형으로

Status: Accepted
Date: 2026-09-25
Supersedes: ADR 028 보완(모양 표)의 가구 부분. 창문 판유리 모양은 그대로다.
Related: ADR 026(침대·문 렌더 모형), ADR 044·046, MVP_SPEC 45.6

## 배경

TASK-SHAPE-001 은 식탁·의자·상자·화덕·물 항아리·종·횃불을 청크 메시 안의 작은 상자 몇 개로 그렸다. 격자 블록과 같은
텍스처·명암이라 "블록 세계의 상자" 로 보였고, 오너는 HR-014·029 에서 "특징이 없어 헷갈린다" 고 했다.
ADR 044 는 소품을 기능이 읽히는 둥근 모형으로 바꾸기로 했다.

## 결정

1. 이 일곱 블록을 `blocks.prop`(렌더 분류)에 더해 청크 메시에서 뺀다. 게임 규칙 필드(solid·opaque·kind·breakSeconds)는 바꾸지 않는다.
2. `FurnitureView` 가 종류마다 `InstancedMesh`(툰) 하나 + 외곽선 `InstancedMesh` 하나로 그린다. 칸 목록은 처음 한 번 청크를 훑고
   이후 `BLOCK_CHANGED` 로만 고친다. 드로우콜은 가구 수와 무관하게 종류 수 × 2(+ 그림자)다.
3. 의자 등받이 방향 규칙(식탁 반대쪽)은 메셔에서 뷰(`chairTurns`)로 옮긴다. 모양 표에는 창문만 남는다.
4. 불꽃처럼 스스로 빛나는 부품은 정점 속성 `unlit = 2` 로 표시해 같은 메시 안에서 빛 번짐을 받게 한다.
5. 가구 아이콘은 같은 모형을 게임 렌더러로 한 번 그려 만든다.

## 검토한 대안

- **모양 표에 상자를 더 넣는다**: 청크 메시·AO·텍스처를 그대로 쓰지만 둥근 형태·툰 명암·외곽선을 줄 수 없다.
- **가구마다 Mesh**: 단순하지만 가구 수만큼 드로우콜이 는다(100 명 마을에서는 가구가 수백).
- **BatchedMesh 한 개**: 드로우콜이 가장 적지만 외곽선·그림자·종류별 재질 관리가 복잡하고, 지금 규모에는 인스턴싱으로 충분하다.

## 예상되는 결과

- 가구가 기능으로 읽히고(화덕 불·냄비, 물 항아리 물빛, 상자 자물쇠) 격자 블록과 구별된다.
- 주방 장면 드로우콜 116 → 94(청크 메시의 모양 면이 빠졌다). 섬 전경은 가구 종류 × 2 만큼 는다(351).
- 큰 마을(X3)에서 인스턴스를 청크별로 나누어 먼 가구를 빼는 컬링이 필요할 수 있다. 지금은 전부 그린다.
