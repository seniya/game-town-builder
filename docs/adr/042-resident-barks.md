# ADR 042. 주민의 한마디: 계기·간격·결정적 문장·DOM 말풍선 (TASK-BARK-001)

Status: Accepted
Date: 2026-09-25
Basis: 사용자 요청(2026-09-25) "마을 사람들이 상황에 맞는 간단한 말을 할 수 있으면 좋겠다", GAME_DESIGN 의 감정 목표, 기존 DialogueSystem(ADR 035)·GratitudePopupView·RoomLabelView 구조. 새 외부 조사 없음.
Related: ADR 007 / 008 / 010 / 017 / 035 / 041
Amends: MVP_SPEC 19.7(신설)·29·30·32.2·34·42, ARCHITECTURE 4.1·5·15·21.4(신설)·24

## 배경

진행 대사(TASK-040)는 목표를 안내하는 모달 대화이고, 들을 대사가 없는 주민에게는 F 가 아무 일도 하지 않았다.
주민이 밭을 갈고 잠드는 모습은 동작(ADR 041)으로만 보였다. 사용자는 주민이 상황에 맞는 짧은 말을 하기를 원했다.

지켜야 할 것:

- MVP_SPEC 42 장은 동적 대사 생성·LLM NPC 를 범위 밖으로 둔다.
- 14.1 의 "결정적이지 않은 유일한 값"(잎의 씨앗 확률)을 늘리지 않는다.
- 주민 100 명 구조(ADR 017): 주민마다 월드를 훑지 않고, 표시와 시뮬레이션을 분리한다.
- 대사로 해금·보상을 주지 않는다(ADR 010).

## 결정

1. **정해 둔 문장을 상황으로 고른다.** 문장은 `data/barks.ts` 에 상황(topic)별로 두고, 창립 주민은 역할별 문장을 우선한다. 생성하지 않는다.
2. **계기는 이미 있는 것만 쓴다.** NPC_ACTION_CHANGED(현재 Action 종류를 registry 에서 읽음)·COMBAT_HIT·RAID_ENDED·ROOM_REGISTERED·VILLAGE_LEVEL_UP·NPC_ARRIVED,
   플레이어와의 거리(0.5 초마다), F(말 걸기). 이벤트 처리 중에 발행하지 않도록 계기를 큐에 모았다가 11 번 슬롯(NPCSystem 뒤)에서 처리한다.
3. **BarkSystem 은 간격·횟수만 소유한다.** 게임 상태를 바꾸지 않고 저장하지 않는다. 출력은 NPC_BARK 알림 하나다(시스템 → 렌더).
4. **간격**: 주민별 공통 10 초 + 상황별 간격(인사 120, 일 90, 도피 30, 맞음 5, 말 걸기 1). 도피·맞음·말 걸기는 공통 간격을 무시한다.
   자는 중·대화 중에는 말하지 않는다. 기절 중에는 맞음 / 기절 문장만 한다.
5. **결정적 문장 선택**: `lines[(hash(npcId) + n) % len]`, n 은 주민·상황별 횟수. 주민마다 시작 문장이 다르고 되풀이하면 돌아가며 바뀐다.
6. **말 걸기의 힌트 우선순위**: 도피 → 기절 → 배고픔 → 잘 곳 없음 → 하는 일. 배고픔·잘 곳 없음은 판단이 쓰는 조건을 읽기만 해서 플레이어가 할 일을 알려 준다.
7. **표시는 DOM 말풍선(`render/BarkBubbleView.ts`)**: 한글 선명도 때문에 방 이름 라벨·+N 과 같은 카메라 투영 DOM 이다. 3.5 초, 카메라 22 칸 안, 가까운 순 최대 4 개.
   재질을 만들지 않으므로 materials.ts 규칙과 무관하다.

## 검토한 대안

- **진행 대사처럼 모달로 띄우기**: 조작을 멈추고 목표 대사와 구별되지 않는다. 한마디는 지나가며 듣는 말이어야 한다.
- **three Sprite + 캔버스 글자**: 가려짐은 자연스럽지만 문장마다 텍스처를 다시 그리고 작은 한글이 흐리다. 기존 라벨이 DOM 이라 방식을 맞췄다.
- **무작위 문장·확률 발화**: 14.1 의 원칙을 깨고 시험을 불안정하게 만든다. 횟수 순환으로 충분히 다양하다.
- **매 프레임 모든 주민의 상황 평가**: 대부분의 계기가 이미 이벤트로 온다. 거리 비교(인사)만 주기적으로 한다.
- **Action 안에서 직접 말하기**: Action 이 표현을 알게 되고 간격 관리가 흩어진다. 한 곳(BarkSystem)에 모았다.

## 예상되는 결과

- 들을 대사가 없는 주민에게도 F 가 반응한다("[F] 말 걸기"). 주민이 배고픔·잘 곳 없음을 말로 알려 준다.
- 말풍선은 벽 뒤에서도 보인다. 거리·개수 제한으로 줄였지만 사람 확인(HR-032)에서 거슬리면 가려짐 판정을 검토한다.
- 문장 수가 적으면 반복이 느껴질 수 있다. 문장 추가는 데이터만 바꾸면 된다.
- 주민 100 명에서 인사 확인은 0.5 초마다 100 번의 거리 비교다. 지역 인덱스가 생기면 그쪽으로 옮긴다.

## 보완 (2026-09-25, TASK-BARK-002): 말할 때의 짧은 소리

사용자가 말할 때 짧은 소리를 넣자고 했다. 결정:

1. **웅얼거림 합성**: 실제 말소리(음성 합성·녹음)가 아니라 글자 두 자마다 짧은 음 하나(1~6 개)를 삼각파 + 저역 필터로 낸다. TASK-050 과 같이 파일 에셋이 없다.
2. **목소리 구별**: 역할별 기본 음높이(목수 196 · 농부 262 · 요리사 349 Hz 부근, 주민은 id 해시로 조금씩 다름)와 글자 코드로 정한 오르내림. 같은 문장은 같은 소리다.
3. **상황 억양**: 도피·맞음은 빠르고 높게, 기절은 느리게 내려가고, "?" 로 끝나면 끝음이 오른다.
4. **거리와 개수**: 말풍선과 같은 22 칸 안에서만, 가까울수록 크게. 동시에 두 주민까지만 내서 여러 주민이 한꺼번에 말해도 시끄럽지 않게 한다.
5. **위치**: 음 목록 계산은 순수 함수(`ui/audio/barkVoice.ts`)로 두고 시험한다. 재생은 `GameSounds` 가 NPC_BARK 를 받아 한다. 역할·거리 조회는 main 이 넘긴다.

검토한 대안: 브라우저 음성 합성(SpeechSynthesis)은 기기마다 목소리·지원이 다르고 문장을 그대로 읽어 한마디의 가벼움과 맞지 않는다. 녹음 파일은 에셋 없이 합성한다는 TASK-050 의 결정과 맞지 않는다.
