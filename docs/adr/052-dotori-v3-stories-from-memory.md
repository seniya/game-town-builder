# ADR 052. V3 이야기가 쌓이는 마을: 기억·결혼·생일·주간 신문

Status: Accepted
Date: 2026-09-27
Related: ADR 049·051, docs/dotori/SPEC.md 11 장, docs/dotori/TASKS.md 5.2, DESIGN 4

## 배경

- 오너는 게임의 재미로 매력적인 그래픽·음악·**몰입되는 플롯**을 꼽았다(메모리). 그러나 손으로 쓴 플롯은 시뮬레이션과 따로 논다.
- 지금 마을에는 이미 사건이 많다: 고백·차임·커플·파티·이사·빵 부족·소문. 다만 한 번 지나가면 사라진다.
  소식 목록은 120 줄에서 잘리고, 일기는 14 줄이며, 주민은 어제를 기억하지 않는다.
- 일기의 6.2 % 가 바로 앞 줄과 같은 문장이다(측정, SPEC 11.5).

## 결정

1. **플롯을 쓰지 않고 사건을 기억으로 남긴다.** 주민마다 "…한 날" 기억 12 개. 대화·아침·기념일에 다시 꺼낸다.
   "그때" 가 나오는 순간 두 사람 사이에 역사가 생긴다.
2. **결혼과 한 집 살림**을 더한다. 오래 사귄 커플이 광장에서 결혼식을 올리고(파티 규칙 재사용), 빈 집으로 함께 옮긴다.
   떠난 자리에 새 주민이 온다. 빈 집이 없으면 "신혼집을 찾는다" 소식이 집을 지을 이유가 된다(V1 가꾸기와 이어진다).
3. **생일**: 28 일 한 해에 한 번, 친한 이웃이 찾아와 축하한다(인사하기 방문 재사용). 새 행사 장소·새 건물은 만들지 않는다.
4. **주간 도토리 신문**: 7 일마다 한 주의 사건을 한 장에 모은다. 멀리서 지켜보던 사람도 "이번 주에 무슨 일이 있었나" 를 한눈에 본다.
   월척(생선 3 %)은 신문의 작은 기삿거리로 더한다.
5. **문장 묶음**: 자주 나오는 일기는 성격별 문장 묶음에서 고르고, 최근 3 줄과 겹치지 않게 한다. 문장은 `data/lines.ts` 에만 둔다.
6. 새 자원·새 직업·새 건물은 없다. 저장 판은 2 를 유지하고 필드만 더한다.

## 검토한 대안

- **LLM 으로 일기·신문을 쓴다**: DESIGN 8 에서 뒤로 미뤘다(비용·오프라인·재현성). 문장 묶음으로 먼저 본다.
- **손으로 쓴 사건 대본(퀘스트)**: 시뮬레이션에서 생긴 일과 겹치지 않고, 반복하면 티가 난다. 생겨난 일을 모으는 쪽을 택했다.
- **결혼하면 한 집을 비우고 남은 사람을 쫓아낸다**: 벌처럼 느껴진다. 빈 집이 있을 때만 옮긴다.
- **생일 잔치를 파티처럼 광장에서 연다**: 파티는 한 번에 하나라 결혼식·파티와 부딪힌다. 방문으로 작게 한다.

## 예상되는 결과

- 주민 카드의 "기억" 과 일기의 "그때" 로 한 사람의 역사가 보인다. 신문이 한 주를 정리해 준다.
- 결혼 → 이사 → 빈 자리 → 새 주민으로 인구 고리가 하나 더 생긴다.
- 위험: 커플이 적으면(처음 1 쌍) 10 일 안에 결혼이 드물 수 있다. 시험은 조건을 만들어 확인하고, 실제 빈도는 측정해 적는다.
- 위험: 문장 묶음이 늘어도 수다 주제 이모지 반복은 남는다. VG3 에서 사람의 판단을 받는다.
