# ADR 026. G2 이후 표현 개선: 침대·문 렌더 모형, 천장 걷어 내기, 밤 밝기

Status: Accepted
Date: 2026-09-23
Basis: [G2 관찰 기록](../state/2026-09-23_2309-task-033-gate-g2-passed.md)의 Q8(문이 열리지 않은 채 통과·눕는 위치·밤 밝기·카메라가 벽에 가림·오브젝트 스케일), headless Chrome 관찰. 새 외부 조사 없음.
Related: ADR 021 / 025
Amends: MVP_SPEC 9.3(천장 걷어 내기), 34(player.ceilingCutRadius / ceilingSearchHeight). ARCHITECTURE 9.3 / 9.4 / 24(BlockDefinition.prop).
블록 규칙(충돌·통행·방 판정·설치·드롭)은 바꾸지 않았다. 새 블록·가구·애니메이션 시스템을 추가하지 않았다.

## 배경

G2 는 통과했지만 확인자가 어색한 점을 짚었고, Phase E 전에 표현을 먼저 손보기로 했다(사용자 결정, 옵션 1).
원인을 보니 여러 지적이 하나로 묶였다. 모든 블록이 1 칸 정육면체로 그려져서 침대는 높이 1 의 빨간 상자, 문은 벽과 같은 두께의 상자였다.
주민은 그 상자 윗면(높이 1)에 누웠고, 문은 열리는 모습 없이 통과했다. 지붕이 있는 집 안에서는 카메라가 벽·지붕에 밀려 플레이어 모형이 화면을 덮었다.

## 결정

1. **`BlockDefinition.prop`**: door / bed 는 청크 메시에서 빼고 render/PropView 가 모양을 그린다. 메셔는 prop 블록을 air 처럼 본다(면을 만들지도 가리지도 않는다).
   충돌·통행·방 판정은 blocks 의 다른 필드를 그대로 쓴다. 침대는 여전히 1 칸 높이의 고체라 플레이어가 올라서면 매트리스보다 조금 위에 선다(알려진 차이).
2. **침대 모형**: 나무 틀·매트리스(윗면 0.46)·이불·베개·헤드보드(anchor 쪽)·발판. 주민은 매트리스 윗면에 눕는다(`BED_SURFACE`).
3. **문 모형**: 칸 가운데 평면의 얇은 판(두 칸 높이). 캐릭터(플레이어·주민)가 수평 1.4 칸 안에 오면 경첩을 축으로 열리고 멀어지면 닫힌다. 열림은 표현일 뿐 문 규칙은 그대로다.
4. **천장 걷어 내기**(MVP_SPEC 9.3): 플레이어 머리 위 6 칸 안에 카메라를 막는 블록이 있으면 그 가장 낮은 y 이상, 수평 7 칸 안을 복셀 셰이더가 그리지 않고 카메라 충돌에서도 뺀다.
   메셔가 지붕에 가려 만들지 않은 벽 윗면은 단면 판(CeilingCapView)으로 덮는다. 없으면 벽 속을 위에서 들여다보게 되어 땅 밑 하늘이 비친다.
5. **카메라가 가까우면 플레이어 모형 숨김**: 0.9 → 1.6.
6. **밤 밝기**: 밤 키프레임의 달빛 0.16 → 0.24, 반사광 0.42 → 0.58, 색 한 단계 밝게. 방향(어두움/밝음)을 보고받지 못해 headless 캡처가 꽤 어두웠다는 사실에 기댄 가정이다. HR-010 에서 확인한다.

## 검토한 대안

- **메셔에 부분 블록 모양 추가(침대 판·문 판)**: 문 여닫이 애니메이션을 청크 메시로는 할 수 없고, 문이 움직일 때마다 청크를 다시 메싱해야 한다.
- **침대 블록 높이(충돌) 자체를 낮추기**: 블록 규칙 변경이다. MVP_SPEC 8.1 / 10.4 와 방 판정 fixture 를 함께 개정해야 한다. 표현 문제를 규칙으로 풀지 않는다.
- **카메라 충돌을 끄고 벽을 투명하게**: 9.3 의 충돌 규칙을 버리게 된다. 천장만 걷어 내면 집 안이 보이면서 벽 충돌은 유지된다.
- **벽 윗면 단면 대신 메셔가 걷어 내기를 알고 면을 만들기**: 걷어 내기 범위가 매 프레임 움직여 청크 재메싱이 계속 일어난다.

## 예상되는 결과

- 방 안에서 주민이 침대에 눕는 모습을 지붕 없이 볼 수 있다. 문은 드나들 때 열린다.
- 모형은 배치 목록 크기에 비례하는 렌더 비용만 든다(침대·문 수). 대형 마을에서 늘어나면 인스턴싱을 검토한다.
- 오브젝트 스케일 지적의 대상(주민·가구·문 중 무엇)은 아직 모른다. 침대·문 모양 개선이 그 일부를 다뤘는지 HR-010 에서 확인한다.
- 물체의 다양성(새 블록·가구)은 MVP 범위 밖이며 ROADMAP 4장의 확장 후보로만 둔다. 애니메이션 추가는 확인자 결정으로 미룬다.
