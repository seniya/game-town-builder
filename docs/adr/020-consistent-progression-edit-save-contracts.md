# ADR 020. 진행 안내·블록 편집·저장의 실행 계약을 일치시킨다

Status: Accepted
Date: 2026-09-22
Basis: 프로젝트 문서 전수 검토와 내부 반례 검산. 새 외부 조사 없음.
Related: ADR 006 / 007 / 008 / 010 / 016
Amends: ADR 006의 역사적 View 예시, ADR 010의 대화 완료·목표 연결, ADR 016의 저장 설명

## 배경

v1.2의 핵심 방향과 콘텐츠 범위는 유지한다. 다만 구현 전 문서에 다음 불일치가 남아 있었다.

- 대사 종료 이벤트에 dialogueId가 없어 완료 대사를 구분하기 어렵고, 대사·명령·저장의
  목표 타입이 서로 달랐다. 늦게 읽은 과거 대사가 현재 목표를 되돌리는 규칙도 없었다.
- 진행 조건은 1차·2차 습격 결과를 따로 요구하지만 EventContext는 lastRaid만 제공했다.
- 설치 흐름은 아이템을 먼저 소비했으며, 단일 칸도 편집 실패 시 함께 복구해야 했다.
- 저장 설명이 진행 중 Action을 저장 시 취소하는지 로드 시 버리는지 모호했다.
- 침대의 사용 위치를 논리 위치로 쓰면 Idle로 로드된 NPC가 고체 안에서 시작할 수 있었다.

## 결정

1. **목표·대사를 식별자로 연결한다.** ObjectiveDefinition을 대사·커맨드·저장에서 공유한다.
   진행 수치는 원천 집계에서 계산한다. DialogueSystem이 미완료 목록·완료 id를 소유하고
   종료 이벤트에 dialogueId를 담는다. ObjectiveSystem은 원천 이벤트 순서를 비교하여
   과거 목표 적용을 무시한다. 첫 Farmer 대화 완료 조건은 기존 명세대로 유지한다.
2. **습격 완료 이력을 읽는다.** RaidSystem이 가진 raidId별 결과 snapshot을 진행 조건에
   제공한다. safetyLevel은 계속 최신 결과만 사용한다. 같은 프레임의 순차 이벤트 평가도
   앞선 이벤트의 완료를 반영한다. 두 종류의 습격 상태를 따로 저장하지 않는다.
3. **아이템과 월드를 함께 확정한다.** BlockEditSystem이 사전 검증·커밋을 조정한다.
   단일 칸과 다중 칸 모두 실패 시 미변경이며 전체 성공 이후에만 알림을 발행한다.
   VoxelWorld가 인벤토리를 소유하거나 상위 시스템을 import하지 않는다.
4. **저장과 로드를 구별한다.** 저장은 프레임 끝의 지속 사실을 분리된 snapshot으로
   복사하며 진행 중 Action·예약을 유지한다. 로드할 때만 임시 Action·예약을 폐기하고
   재판단한다. 비동기 쓰기는 최신 순서를 보장하며 실패 시 이전 슬롯을 보존한다.
5. **사용 자세와 충돌 위치를 구별한다.** NPC의 body.pos는 접근 셀에 유지한다.
   EntityView가 Action의 시설·사용 자세를 읽고 usePosition에서 표현한다.
   렌더 위치를 게임 상태나 저장 위치에 역으로 쓰지 않는다.

구체 계약은 [ARCHITECTURE](../project/ARCHITECTURE.md) 6 / 12 / 20~23 / 28장,
규칙은 [MVP_SPEC](../project/MVP_SPEC.md) 10 / 12 / 27 / 32장을 따른다.
기존 Task의 완료 조건에 반례를 추가하며 새 콘텐츠 Task나 메커닉을 만들지 않는다.

## 검토한 대안

- 과거 대사를 삭제하거나 진행을 대사 읽기에 묶기: 안내 누락과 진행 잠금을 만들므로 기각.
- 목표를 텍스트로만 저장하고 로드 시 추측하기: 집계 종류와 순서가 사라지므로 기각.
- 이벤트 시스템에 별도 습격 플래그 복제: 상태 소유자가 둘이 되므로 기각.
- 저장할 때 모든 행동을 취소하기: 자동 저장이 생활 장면을 끊으므로 기각.
- Action 전체를 저장하기: 기존 ADR 016의 지속 사실/임시 실행 분리 원칙을 유지한다.
- 가구 사용 위치를 충돌 위치로 쓰고 로드 시 탈출시키기: 렌더 자세 때문에 고체 안에
  들어가는 상태를 만들 필요가 없으므로 접근 위치와 시각적 자세를 분리한다.

## 예상되는 결과

대사 지연·같은 날 두 레벨 달성·비동기 저장·편집 실패에도 단일 상태 소유권을 유지한다.
알림 발행 시점과 snapshot 복사 비용을 구현에서 확인해야 한다.
시설 사용 자세의 보간, 접근 셀 파괴와 충돌 복구는 브라우저에서 확인해야 한다.

이 결정은 구현·재미·성능 통과 기록이 아니다. 수치·방 레시피·보상·해금은 바꾸지 않는다.
