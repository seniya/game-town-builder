# 제안: 살아 있는 마을 시뮬레이션 시험판 (도토리 마을)

Date: 2026-09-26
Status: 진행 중 (오너 지시로 시험판 개발)
Evidence: [Generative Agents 조사](../research/2026-09-26-generative-agents.md), [CC0 3D 에셋 팩 조사](../research/2026-09-26-cc0-3d-asset-packs.md)

이 문서는 본 게임의 정본(GAME_DESIGN / MVP_SPEC / ARCHITECTURE / TASKS)을 바꾸지 않는다.
본 게임과 떨어진 `prototypes/dotori-village/` 에서 방향을 탐색한 기록과 제안이다.
본 게임에 무엇을 옮길지는 오너가 시험판을 보고 결정한 뒤, 그때 정본과 ADR을 개정한다.

## 1. 배경

2026-09-26 대화에서 오너가 말한 것은 다음과 같다.

- 지금까지 만든 DQB2형 결과물이 생각보다 재미없다.
- 오너가 생각하는 게임의 재미는 매력적인 그래픽, 아름다운 음악, 몰입되는 플롯이다.
  오너는 이 셋에 자신이 소질이 없다고 느낀다.
- 어쩌면 시티빌더나 도시건설 시뮬레이션을 원했던 것 같다.
- 어릴 적부터 컴퓨터로 세상과 삶을 시뮬레이션해 보고 싶은 꿈이 있었다.
  능력과 컴퓨팅 파워의 한계 때문에 공상으로만 남겨 두었다.
- 너무 사실적인 시뮬레이션이 재미있을지는 모르겠다.

같은 대화에서 에이전트가 짚은 점은 다음과 같다.

- 부품(효과음, 연출, 전투)은 하나하나 좋음으로 통과했지만, 흐름 전체를 치트 없이 플레이해 본 적은 적다.
- 시뮬레이션 계열의 재미는 사실성이 아니라 과장, 압축, 인과, 놀람에서 나온다.
  이런 게임에서 플롯은 쓰는 것이 아니라 생겨난다(드워프 포트리스, 림월드, Generative Agents).
  그래서 오너가 약하다고 느낀 플롯과 그래픽의 부담이 줄어든다.
- 주민 100명과 대형 월드라는 기존 구조 원칙은 원래 이 꿈의 규모와 맞는다.

## 2. 지금까지 만든 것

도토리 마을 2D 시험판은 브라우저 한 페이지로, 버려도 되는 실험이다.

- 2D 판: <https://claude.ai/artifact/RfmXdrbSB1jYyCRQmVFJJ7>
- 3D 판: <https://claude.ai/artifact/NBoPPzTWGjFH2Pct7rixA7>
- 코드: `prototypes/dotori-village/` ([README](../../prototypes/dotori-village/README.md))
- 위에서 내려다보는 64×40 타일 마을에 주민 30명이 산다.
  - 성격 10종: 수다쟁이, 게으름뱅이, 일벌레, 로맨티스트, 투덜이, 겁쟁이, 먹보, 호기심쟁이, 파티광, 외톨이
  - 직업 7종
- 욕구(배부름, 기운, 어울림, 즐거움)와 성격 가중치로 행동을 고르는 규칙 기반 AI다.
  대화, 호감도, 짝사랑과 고백, 소문 전파, 파티, 비, 유령 소문 공포가 있다. LLM은 쓰지 않는다.
- 첫날 밤 파티: 파티광 한 명에게 생각 하나만 심고 시작한다. Generative Agents의 발렌타인 파티를 본떴다.
- 오너가 쓸 수 있는 개입은 "생각 심기" 세 가지다(파티, 고백, 유령 소문).
- 2판에서 머리가 큰 캐릭터와 행동별 동작을 넣었다.
  걷기, 괭이질, 도끼질, 낚시, 대화, 말다툼, 춤, 낮잠, 도망, 우산을 절차적으로 그린다.

오너의 반응은 다음과 같았다.

- 1판: "잘 만들었네. 캐릭터와 행동 애니메이션이 정교해지면 흥미로울 것 같다."
- 2판 뒤: Anno 1800 / 117처럼 더 정교한 애니메이션과 오브젝트를 만들 수 있는지 물었다.

## 3. 제안

Anno 수준의 정교함은 대형 스튜디오의 수작업 에셋과 애니메이션에서 나온다.
에이전트가 코드로 그리는 방식으로는 따라갈 수 없다.
대신 다음 세 갈래로 "살아 있는 마을"의 밀도를 올린다.

### 3.1 3D 에셋 팩 판 (2026-09-26 1판 게시)

시뮬레이션 규칙은 그대로 두고, 그리는 쪽만 CC0 3D 에셋으로 바꾼 판을 만든다.

- 주민: Kenney Mini Characters. 동작은 걷기, 달리기, 앉기, 줍기, 휘두르기, 끄덕임 등을 쓴다.
- 건물, 나무, 소품: KayKit Medieval Hexagon Pack과 Kenney Fantasy Town Kit 일부.
- 렌더러: Three.js(본 게임과 같은 0.186.0). 비스듬히 내려다보는 카메라로 이동, 회전, 확대를 한다.
- 낮과 밤, 그림자, 불빛, 굴뚝 연기, 감정 입자, 말풍선을 넣는다.
- 2D 판과 같은 시뮬레이션 코드(`sim.js`)를 공유한다. 두 판을 나란히 놓고 "계속 보고 싶은가"를 비교할 수 있다.

### 3.2 분주함과 생산 체인 (다음 후보)

- 밭에서 밀을 거둬 수레로 방앗간과 빵집에 나르는 식으로 생산 과정을 눈에 보이게 한다.
- 길을 오가는 사람, 수레, 배를 늘린다.
- Anno다운 즐거움의 상당 부분이 여기서 나온다고 본다. 가설이며 시험판으로 확인한다.

### 3.3 드문 순간만 LLM (나중 후보)

순간순간의 행동은 규칙으로 처리하고, 하루 계획, 대화 내용, 일기, 소문 문장만 LLM으로 만든다.
비용 수치는 아직 확인하지 않았다([조사](../research/2026-09-26-generative-agents.md)).

## 4. 판단 기준

오너에게 받을 답은 다음과 같다. 사람의 판단이므로 `docs/project/HUMAN_REVIEW.md` 의 HR-037 로 대기시키고,
에이전트의 관찰로 대신하지 않는다.

1. 5분 들여다봤을 때 계속 보고 싶었는가, 손이 금방 떠났는가
2. 마음이 움직인 순간은 무엇이었나 (파티, 특정 주민의 일기, 소문, 동작)
3. 2D 판과 3D 판 중 어느 쪽이 더 보고 싶은가, 이유는 무엇인가
4. 어색하거나 거슬린 동작, 모양은 무엇이었나

## 5. 본 게임과의 관계

- `prototypes/` 는 본 게임 코드(`src/`)와 섞이지 않는다. 본 게임의 빌드, 테스트, 린트에 들어가지 않는다.
- AGENTS.md 7장(새 메커닉, 새 프레임워크 임의 추가 금지)은 본 게임 범위의 규칙이다.
  이 시험판은 오너의 명시적 지시(2026-09-26 "너의 제안을 문서로 남기고 해당 개발을 능력껏 진행하자")로 진행한다.
- 오너가 방향을 확정하면 GAME_DESIGN의 핵심 문장부터 개정 여부를 결정한다.
  예를 들어 "직접 짓는 DQB2형"에서 "내려다보며 가꾸는 살아 있는 마을"로 바꿀지다.
  그다음 MVP_SPEC, ARCHITECTURE, TASKS와 ADR을 차례로 고친다. 그 전까지 본 게임의 정본은 그대로다.
