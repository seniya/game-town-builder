사용자 요청(2026-09-25) "마을 사람들이 상황에 맞는 간단한 말을 할 수 있으면 좋겠어"로 기획해 추가했다.
정본을 먼저 고쳤다. MVP_SPEC 19.7 에 계기·간격·우선순위·표시 규칙을, 34 장에 `bark` 수치를 두고 ARCHITECTURE 21.4 에 BarkSystem 계약을 적었다. TASKS 2.3 의 9 와 Task 본문을 더했다.

## 기획 요약

- 주민은 **정해 둔 짧은 문장**을 상황에 맞게 머리 위 말풍선으로 말한다. 생성하지 않는다(42 장의 LLM·동적 대사 제외는 그대로다).
- 모달이 아니다. 조작·시간을 멈추지 않고 게임 상태(Action·저장소·포인트·목표·진행 대사·저장)를 바꾸지 않는다.
- 계기는 이미 있는 것뿐이다: Action 전환(농사·조리·수리·식사·취침·쉬기·도피·기상), 맞음·기절, 습격 끝, 새 방(인식·타입 변경), 마을 레벨, 도착, 플레이어 접근(인사), F(말 걸기).
- 진행 대사가 없는 주민에게 F 를 누르면 "[F] 말 걸기" 로 한마디를 듣는다. 도피 → 기절 → 배고픔 → 잘 곳 없음 → 하는 일 순으로 골라, 배고픔·잘 곳 없음이 플레이어의 할 일 힌트가 된다.
- 문장 고르기는 결정적이다(주민 id 해시 + 횟수 순환). 14.1 의 유일한 무작위를 늘리지 않는다.

## 검증

- `pnpm test` 57 파일·498 시험 통과(새 `bark.test.ts` 12). typecheck·eslint(src·tests)·prettier·build 통과.
- headless Chrome 148(`vite preview`, 1280 × 720), 관찰용으로 `__gtbScreen.lockAcquired()` 로 일시정지를 풀고 카메라를 주민 뒤에 고정했다.
  - `?scene=kitchen-lab`: 플레이어가 다가가자 요리사·목수·농부가 인사("오늘도 잘 부탁해." / "좋은 아침!" / "일찍 일어났네."). 말풍선은 머리 위 "!" 바로 위에 뜬다.
    `poke` 로 세 주민이 역할별 잡담("흙 냄새가 좋아." / "간은 내가 잘 맞춰." / "튼튼한 벽이 최고지."). 요리사 조리 시작 "맛있게 만들어 줄게.",
    밤에 침대 없는 목수·요리사 "잘 곳이 없네…" / "오늘도 밖에서 자야 하나.", 침대가 있는 농부 "오늘도 고마웠어."
  - 가까운 두 주민의 말풍선이 겹치는 것을 처음 관찰에서 찾아, 겹치면 위로 쌓도록 고쳤다.
  - F 경로: 진행 대사가 남은 목수를 조준해 F → 대사 상자("나는 목수야…"). 진행 대사를 모두 마친 뒤 조준하면 프롬프트 "[F] 말 걸기", F → 모달 없이 "튼튼한 벽이 최고지."
    (kitchen-lab 은 진행 이벤트가 곧 새 대사를 등록하므로 같은 평가 안에서 대사를 마치고 조준했다. 월드를 바꾸는 조작은 하지 않았다.)
  - `?scene=perf&residents=100&time=19.9` 20 초: 한마디 79 회(취침 78·새 방 1), 동시에 보인 말풍선 최대 2 개(전경 카메라라 22 칸 제한), 예외 없음.
- 보지 못한 것: 식사(kitchen-lab 은 food 0 으로 시작해 점심을 먹지 않음)·도피·맞음·습격 끝·마을 레벨·도착 말풍선은 headless 로 보지 못했고 시험으로만 확인했다. HR-032 에 넣었다.

## 결정

- ADR 042: 정해 둔 문장 + 이벤트 계기 + 주민별 간격 + 결정적 순환 + DOM 말풍선. 모달·Sprite 글자·무작위·Action 안 발화는 택하지 않았다.

## 아직 없는 것과 다음 할 일

1. HR-032(말의 빈도·반복·말투·말풍선 가독성)를 HR-029·030 과 함께 본다. 부정적이면 간격·문장·표시 시간을 조정한다. 새 계기나 메커닉은 더하지 않는다.
2. 말풍선은 벽 뒤에서도 보인다(방 라벨과 같은 방식). 거슬린다는 판단이 나오면 가려짐 판정을 검토한다.
3. 음성(짧은 소리)은 넣지 않았다. 필요하면 TASK-050 의 합성 오디오에 별도 결정으로 더한다.
4. 장기 규모: 인사 확인은 0.5 초마다 주민 수만큼의 거리 비교다. 지역 인덱스가 생기면 옮긴다.
