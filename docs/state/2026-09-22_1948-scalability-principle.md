## 변경 내용

사용자 요청에 따라 다음 원칙을 AGENTS.md, README, 기획·명세·아키텍처에 저장했다.

> MVP는 주민 최대 5명을 구현하지만, 아키텍처는 주민 100명과 대형 월드로 확장 가능해야 한다.

- ARCHITECTURE 2.3: 가변 주민 컬렉션, 데이터로 주입하는 월드 크기, 청크 처리,
  공유 작업 예산, NPC 판단·Action 실행 책임, Entity/View 분리, 저장 입출력 경계를 명시했다.
- ADR 017: 배경·결정·대안·예상 결과를 기록했다. 스트리밍과 원거리 시뮬레이션은
  확장 단계에서 미로드 상태·공간 경계·저장 계약부터 구체화한다.
- TASK-003/028: 다른 크기의 월드 fixture와 100개 NPC id registry 검증 기준을 추가했다.
- TASK-053: 확장 경계 검토와 남은 병목 기록을 추가했다.

MVP 인원·월드 크기·게임 수치와 Task 실행 순서는 유지한다.
100명 콘텐츠 구현은 추가하지 않았다. 대형 월드의 구체 크기와 동시 활성 범위,
장치별 성능 예산은 확장 전에 확정할 항목으로 남겼다.

## 검증

- Markdown 형식·문서 참조와 변경 diff를 확인했다.
- 기존 명세 검증 스크립트의 문서 검사, 53개 Task 의존 순서, 공간 판정 예시,
  수치·시간 검산이 통과했다.
- `git diff --check`를 통과했다.
- 구현 코드가 없으므로 새 fixture 검사·브라우저 실행·100명 성능 검증은 수행하지 않았다.
  어떤 구현 Task도 완료 처리하지 않았다.
