README·AGENTS, ADR 001~019, research 4개, 기존 state 10개와 도구용 graft/INDEX를

**아름다운 공간과 정감 있는 주민의 생활**이라는 방향은 유지한다.
건축·인식·사용의 시스템 축과 공간·주민에 대한 애착을 검증하는 감성 축은 서로

장기 구조의 구체 구현을 첫 취침보다 앞당기거나 새 콘텐츠로 범위를 넓히지 않았다.

## 문서의 신뢰도와 방향성 정리

- [문서 안내](../README.md)를 추가했다. 정본·결정·조사·과거 기록을 구별한다.
- ADR 006의 NPC.view 예시와 ADR 010의 “대화 완료에 의존하는 이벤트 없음”은
  현재 적용되지 않는다고 머리말을 보완했다. 역사적 본문은 보존했다.
- 2D 상태 기록, v1.0 재설계 기록과 이전 검토의 미검증 성능 단정에 보정 안내를 달았다.
  파일명 시각만으로 최신 규칙을 고르는 것을 금지했다.
- 기존 스택 조사에서 드로우콜 수만으로 WebGPU를 검토하는 낡은 결정 매핑을
  ADR 019 기준으로 맞췄다. 외부 링크·패키지 버전·시장 자료를 새로 조사하지 않았다.
- 원경 비용은 CPU/GPU를 각각 측정하도록 정리했다. CPU만의 병목이나 100명에서
  특정 최적화의 필수성을 실측 없이 단정하지 않는다.
- DQB2 세 루프는 프로젝트의 해석이라고 명시하고 다른 게임에 관한 불필요한 단정을
  제거했다. 설계상 엔진 변경을 실제 코드 이전의 성공 사례처럼 표현하지 않는다.

## 구현 전에 확정할 열린 정책

다음은 현재 문서만으로 한 가지 동작을 결정할 수 없는 항목이다. 이번 검토에서
새 밸런스·메커닉을 임의로 정하지 않았다. 해당 Task를 시작할 때 기존 범위 안에서
정본과 완료 조건을 먼저 구체화한다. TASK-001의 셋업을 막는 항목은 아니다.

## 검증

- 문서의 코드 펜스 짝, 로컬 링크/앵커, 현재 정본의 장 참조와 ADR/Task 참조를 검사했다.
- Task 001~053과 PERF 2개의 중복·누락, 실행 순서, 선행 의존을 검사했다.
- 목표의 원천 이벤트 순서와 인구별 food/housing 계산, 자정 전후 시각 및 두 습격·도착
  예약의 경계 사례를 임시 Python 검산으로 확인했다. 이는 게임 구현 테스트가 아니다.
- MVP 34장의 balance, 블록/레시피/해금/레벨 비용 표와 Task 실행 순서는 기준 커밋과 동일하다.
- `git diff --check`를 수행했다. 어떤 Task 체크박스도 완료 처리하지 않았다.
- 실행 코드가 없어 pnpm test/build·브라우저 플레이는 수행하지 않았다. 성능·분량·재미는
  여전히 미검증이다. 특히 실제 조리·수확·이동 시간은 산술만으로 보장할 수 없다.
