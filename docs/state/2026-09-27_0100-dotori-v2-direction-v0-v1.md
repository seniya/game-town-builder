# v2 도토리 마을: 방향 전환, V0 이식, V1 가꾸는 마을

Date: 2026-09-27 01:00

## 배경

- 오너(2026-09-26): 시험판 도토리 마을이 "내가 지시하여 만들었을 때보다 더 멋지고 근사하게 나왔다".
  이어서 "나의 계획보다 너의 판단을 믿겠다. 스스로 로드맵을 만들고 게임의 방향성을 잡고 계속 개발을 진행하자. 하루 정도의 개발 후에 확인해보겠다".
- 에이전트 판단: 시험판 방향(내려다보는 살아 있는 마을)을 본 게임으로 채택하고, 시험판에 없던
  "플레이어가 공간을 만든다" 를 첫 핵심 기능으로 둔다. 최상위 목표 문장("아름답게 만든 공간에서 정감 있는 주민이 실제로 살아가는 순간")은 그대로다.

## 검증

- `pnpm test` 564 건 통과(도토리 17 건 포함: 결정성, 이틀 진행·파티, 경로 예산, 주민 100 명 하루, 놓기 검사, 목재 흐름, 집 완성, 벤치 첫 사용,
  이사·인사, 치우기, 저장 왕복 결정성). `tsc --noEmit` 통과. eslint 오류는 추적하지 않는 `.claude/` 파일에서만 나온다.
- 한 번은 시간에 민감한 v1 시험 하나가 흔들렸고 다시 돌리자 통과했다(원인 확인 안 함).
- node 계측: 20 명 4 일(5760 틱) 약 300 ms. 걷는 시간 비율 42 % → 32 %(1× 6 틱, 걸음 0.33, 가까운 목적지, 활동 길이 늘림).
- headless Chrome(ANGLE Vulkan)으로 `vite preview` 와 게시 묶음을 열어 확인: 첫 화면, 발자국 미리보기·이유 문구, 공사장(비계·진행 막대·목재 수),
  꽃밭 완성, 저녁 빛(조정 뒤), 밤 광장 불빛, `?scene=grown` 이틀 반 뒤 마을(인구 23). 콘솔 오류 없음(합성 포인터 이벤트의 setPointerCapture 예외는 시험 도구 탓).
- **게시된 아티팩트 페이지는 직접 열어 보지 못했다.** 같은 파일을 로컬에서 연 것만 확인했다.
- 실제 창의 부드러움·fps 는 재지 못했다(headless 는 수직 동기에 묶임).
